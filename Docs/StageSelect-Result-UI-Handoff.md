# 오르비스탑 RPG — 스테이지 선택·결과 화면 UI 제작 인계서

- 작성일: 2026-11-13
- 목적: 다른 에이전트가 이 문서 하나를 기준으로 두 화면의 디자인·UI 구조·연출을 제작할 수 있도록 정리한다.
- 문서 성격: 사용자와 논의한 구성안의 제작 브리프. 아래 제안값이 모두 확정된 게임 규칙이거나 이미 구현됐다는 뜻은 아니다.
- 이번 문서 작성에서는 게임 코드·UI·기존 GDD를 변경하지 않았다.

## 1. 제작 목표와 범위

스테이지 선택은 **층 탐색 → 지역·적·보상·별 미션 확인 → 입장** 흐름의 전체 화면으로 만든다. 결과 화면은 **이번 판 성과 → 새 별 → 획득 보상 → 다음 행동** 순서로 읽히게 만든다.

사용자 요구:

1. 플레이를 누르면 왼쪽에서 층 목록을 스크롤하고, 선택한 층의 정보는 오른쪽에서 확인한다.
2. 입장은 별도의 입장 버튼으로 실행한다. 층 선택 자체로 입장하거나 에너지를 소모하지 않는다.
3. 스크롤이 불편하므로 뒤쪽 레이캐스트·입력 가로채기를 점검한다.
4. 선택 시 상세 정보가 부드럽게 나타나는 등 코드 기반 게임 연출을 적용한다.
5. 팝업에 얽매이지 않고 화면 전체를 활용할 수 있다.
6. 층마다 별 미션과 보상이 있으며, 미션 조건은 모든 층에 공통이다.

UI 제작과 별 시스템 구현은 구분한다. 별 저장·판정·보상 지급이 없는 상태라면 화면과 데이터 연결 인터페이스를 준비하되 완료된 기능으로 보고하지 않는다. 실제 보상을 클라이언트 UI에서 지급하지 않는다.

숫자·별·보상은 배치 설명을 위한 예시이며 실제 계정 상태를 나타내지 않는다.

### 4.2 권장 영역 배분

- 상단 헤더 약 120px, 하단 행동·누적 보상 영역 약 150px.
- 본문 왼쪽 약 35~40%, 오른쪽 약 60~65%. 실제 리소스와 가독성에 맞춰 조정한다.
- 우측 상단 MSW 시스템 메뉴와 모바일 안전 영역을 침범하지 않는다.
- 목록·상세·하단 버튼은 서로 독립된 부모 컨테이너로 구성한다.
- 정보가 넘치면 상세 정보 안에만 별도 스크롤을 두고, 입장 버튼은 고정한다.

### 4.3 왼쪽 목록

- 각 행: 층 번호, 층 이름, 획득 별 0~3개, 클리어·도전 가능·잠김 상태.
- 선택한 층과 가장 높은 도전 가능 층은 서로 다른 표식으로 구분한다.
- 잠긴 층도 선택해 내용을 볼 수 있다. 입장만 불가하다.
- 최초 진입은 현재 도전 층을 선택하고, 해당 행이 보이도록 스크롤한다.
- 같은 화면을 잠깐 닫았다 다시 열 때 선택·스크롤 유지 여부는 일관되게 처리한다.
- `현재 도전 층으로`는 목록 이동과 오른쪽 정보 선택을 함께 수행한다.
- 지역 필터와 별 보상 구간 표시의 기준을 명확히 라벨링한다.
- 315층을 지원한다. 새 층 추가 시 코드에 개수를 다시 하드코딩하지 않는다.

### 4.4 오른쪽 정보

위에서부터 다음 순서로 구성한다.

1. 지역 배경 미리보기. 층 번호보다 지역 분위기가 먼저 보이도록 한다.
2. 층 번호·이름·누적 별. 잠금 조건 또는 클리어 상태를 함께 표시한다.
3. 실제 등장 몬스터 3~5종 미리보기. 종류가 많으면 더 보기. 강화 몬스터는 구분한다.
4. 공통 별 미션 3개와 각 미션 보상 상태.
5. 클리어 확정 보상 / 확률 획득 보상. 실제 드롭 대상과 수량을 확인해서 연결한다.
6. 입장 버튼. 정상은 `입장 · 에너지 3`, 잠김은 해금 조건, 로딩은 준비 상태를 표시한다.

몬스터를 누르면 이름·간단한 특징을 보여준다. 데이터가 없는 전투력·권장 스펙·특성은 임의 생성하지 않는다.

### 4.5 별 미션과 누적 보상 UI

- 미션별 상태: 미달성 / 기존 달성 / 이번 판 신규 달성.
- 별 달성과 보상 수령은 별도 상태로 표현할 수 있게 한다.
- 이미 얻은 별을 재도전마다 새 보상처럼 연출하지 않는다.
- 구간 상자 상태: 잠김 / 수령 가능 / 수령 중 / 수령 완료 / 수령 실패.
- 상자를 누르면 보상 내용을 미리 볼 수 있어야 한다.
- 구간 마지막이 10층 미만일 경우 최대 별과 상자 조건을 데이터로 처리한다.
- 미정 보상은 실제 값처럼 넣지 말고, 제작용 프리뷰 데이터로만 분리한다.

## 5. 결과 화면

### 5.1 클리어 결과

```text
                     19층 클리어!

                       ★ ★ ☆
                     신규 별 +1

     ✓ 층 클리어                         이전 달성
     ✓ 제한 시간 내 클리어               이번 판 달성
     ○ 체력 50% 이상으로 클리어           남은 체력 38%

     전투 시간 02:18                      목표 시간 [미정]

     전투 보상        [스킬북] [깃털] [주문서]
     신규 별 보상     [이번에 새로 받은 보상]

     구간 누적 별 18 → 19 / 30
     [상자 수령 가능 시 안내]

     [층 선택으로]                 [다시 도전 · 에너지 3]
```

- 큰 별은 계정에 누적된 해당 층 별을 보여준다.
- 미션 행은 이번 판의 실제 판정과 이전 달성 여부를 구분한다. 예전에 달성했지만 이번 판은 실패한 조건도 구분 가능해야 한다.
- 전투 보상과 별 최초 달성 보상을 분리한다. 기존 보상 합계에 별 보상이 중복 표시·지급되지 않게 한다.
- 신규 별 0개, 보상 0개, 최고 기록 갱신 여부 등 모든 조합을 지원한다.
- 구간 상자 안내는 선택 화면의 해당 구간으로 연결하는 방식이 좋다.

### 5.2 패배·중도 포기 결과

- 제목: `도전 종료` 또는 `탐험 중단`.
- 도달 층·스테이지, 획득한 전투 재료, 기존 최고 기록을 표시한다.
- 제안된 별 조건은 모두 클리어가 전제이므로 패배·포기 시 신규 별을 부여하지 않는다.
- 기존 별은 유지하고, 아직 수령하지 않은 구간 보상을 잃지 않는다.
- `획득한 보상`은 실제로 정산된 값만 표시한다. 실패해도 유지되는 재료 정책은 기존 게임 로직을 따른다.

### 5.3 하단 행동

- `층 선택으로`: 로비로 이동한 뒤 선택 화면을 열고, 방금 플레이한 층을 선택하는 목표 흐름.
- 현재 `OnLobby()`는 로비 이동 요청이다. 위 목표 흐름은 선택 상태 전달·도착 후 자동 열기 연결이 추가로 필요하다.
- `다시 도전`: 방금 플레이한 층을 같은 구성으로 재시작하고 에너지 3개를 소모한다.
- 에너지 부족 시 부족 수량·다음 충전 시간을 보여주고 입장을 막는다.
- 정산·저장·입장 처리 중 연속 클릭을 막는다. 서버 판정을 최종 기준으로 삼는다.

## 6. 연출 명세

| 상황 | 제안 연출 | 권장 길이 |
|---|---|---|
| 선택 화면 진입 | 목록이 왼쪽에서 이동·페이드, 상세가 이어서 등장 | 0.25~0.35초 |
| 같은 지역의 다른 층 선택 | 상세의 짧은 슬라이드·페이드, 선택 테두리 이동 | 0.18~0.28초 |
| 지역 변경 | 배경 크로스페이드, 몬스터·보상 갱신 | 약 0.3초 |
| 입장 | 버튼 반응 → 선택 지역으로 소폭 확대 → 기존 화면 전환 연결 | 반복 대기 최소화 |
| 클리어 | 타이틀 → 기존 별 표시 → 신규 별만 점등 → 보상 표시 | 스킵 가능 |
| 구간 상자 달성 | 상자의 작은 빛 효과·수령 가능 표식 | 과도한 반복 금지 |

- 연속 선택은 마지막 선택을 우선한다. 이전 tween·콜백이 새 상세를 덮어쓰지 않도록 취소·갱신한다.
- 연출 중에도 스크롤은 가능해야 한다. 이동 중 오클릭으로 입장하지 않도록 한다.
- 카드 선택·UI 연출 시간을 제한 시간 미션에 포함하지 않는다.
- UI 이동은 `anchoredPosition`, 그룹 페이드는 `CanvasGroupComponent.GroupAlpha`로 처리한다.
- 닫기·맵 전환·OnEndPlay 시 이벤트와 연출 상태를 정리한다.

## 7. 스크롤·레이캐스트 필수 점검

사용자가 실제로 스크롤이 불편하다고 보고한 영역이다. API로 위치를 바꾼 것만으로 조작 검증을 통과시키지 않는다.

- 목록 행, 행 사이 여백, 목록 배경 위에서 각각 휠·드래그를 확인한다.
- 뒤의 전체 화면 배경·딤·이전 로비 버튼이 목록 입력을 가로채지 않게 한다.
- 장식용 배경·텍스트·이미지의 불필요한 RaycastTarget을 끈다.
- 목록 입력 표면은 리스트 자식·부모 관계와 정렬 순서를 함께 확인한다.
- 커스텀 휠과 네이티브 스크롤이 같은 입력에 두 번 반응하지 않게 한다.
- 목록 밖에서 휠을 굴릴 때 목록이 이동하지 않도록 한다.
- 휠 보간 도중 사용자가 드래그를 시작하면 이전 보간 목표가 사용자의 손동작을 되돌리지 않도록 한다.
- 드래그 후 손을 뗄 때 행 선택이 잘못 발생하지 않는지 확인한다.
- PC 스크롤바를 너무 가늘게 만들지 않는다. 모바일에서도 드래그 영역을 넓게 확보한다.
- ScrollLayoutGroup은 빈 영역·마우스 휠 처리가 까다롭다. 현재 구현을 점검하고 필요하면 GridView를 검토한다. 변경 시 기존 315개 행 생성·이벤트 연결 방식을 함께 정리한다.

## 8. 현재 프로젝트 연결 지점

## 9. 새 데이터 연결 계약 — 이름은 예시

아래는 UI가 필요로 하는 의미 단위다. 실제 데이터셋 컬럼·프로퍼티가 이미 존재한다고 가정하지 않는다.

| 단위 | 필요한 정보 |
|---|---|
| 층 | floorId, 이름, 지역, 잠금·도전 상태, 배경 RUID, 몬스터 목록 |
| 보상 | 종류, 아이콘 RUID, 수량, 확정/확률, 필요 시 확률 설명 |
| 별 미션 | missionId, 조건 설명, 목표값, 누적 달성 여부, 별 보상 수령 상태 |
| 판 결과 | 클리어/패배/중단, 전투 시간, 종료 체력 비율, 이번 판 조건별 성공 여부 |
| 별 변경 | 판 시작 전 별, 판 종료 후 별, 이번 판 새로 얻은 별, 신규 보상 |
| 구간 | 구간 ID, 포함 층 목록, 총 별, 최대 별, 상자별 요구 별·수령 상태 |

- 별 판정·저장·보상 중복 방지는 서버 담당이다.
- 별을 합계 숫자 하나로만 전달하지 말고 조건별 달성 여부도 전달한다.
- 시간 목표가 미정인 제작 단계에서는 `목표 시간 미정` 또는 프리뷰 전용 값을 사용한다.
- 실제 저장값과 프리뷰용 예시값은 분리한다.

## 10. MSW 제작 규칙과 검증 기준

- 프로젝트 `AGENTS.md`를 먼저 따른다. Foundation·UI·스크립팅 스킬과 요청 영역의 참조를 로드한다.
- `.ui`의 조회·수정은 UIBuilder를 사용한다. raw JSON을 직접 수정하지 않는다.
- 새 런타임 스크립트가 필요하면 `RootDesk/MyDesk/<Feature>/` 아래 작성한다. `.codeblock`은 직접 수정하지 않는다.
- UI는 클라이언트 전용이며 저장·재화·별 지급은 서버에서 처리한다.
- 파일 변경 전 Maker 플레이를 종료하고, 변경 후 Refresh·빌드 로그·Play·런타임 로그로 확인한다.
- 기존 입장 비용·중복 차감 방지·저장 실패 시 입장 차단을 유지한다.

완료 기준:

1. 실제 PC 휠과 모바일 드래그에서 목록 탐색이 자연스럽고 빈 영역에서도 입력이 끊기지 않는다.
2. 현재 도전 층 이동, 잠긴 층 미리보기, 별·상세·보상 갱신이 일치한다.
3. 에너지 부족·데이터 로딩·입장 처리 중 상태가 표시된다.
4. 빠른 연속 선택·닫기·재열기에도 상세 정보와 애니메이션이 어긋나지 않는다.
5. 결과의 기존 별·신규 별·별 보상·전투 보상을 구분한다.
6. 클리어·패배·중도 포기·신규 별 없음·전부 달성·보상 수령 실패 상태를 확인한다.
7. 미구현 별 기능과 미정 보상값을 명확히 보고한다. 화면 목업을 시스템 구현 완료로 보고하지 않는다.
8. 빌드·런타임 오류 없이 바인딩과 기능 실행의 긍정 로그 증거를 남긴다.

권장 작업 순서: **현재 코드 확인 → 전체 화면 정보 구성 → 스크롤 입력 검증 → 별 UI·데이터 연결 → 결과 화면 → 연출·해상도 검증**.
