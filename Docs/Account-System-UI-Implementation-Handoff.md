# 계정 성장 시스템·계정 정보 UI 구현 인계서

- 작성일: 2026-11-14
- 목적: 다른 에이전트가 계정 레벨 시스템과 최종 논의된 계정 UI를 구현하는 데 사용하는 단일 인계서.
- 상태: 2026-11-14 시스템·UI·리소스 구현. Maker 검증 내용은 문서 끝의 구현 현황 참고.
- 우선순위: 최신 사용자 지시 → 이 문서 → 과거 `Account-Level-Progression-UI-Plan.md`. 과거 문서의 좌측 상단 진입·가로 로드맵·누적 효과 보기는 최신 UI안에서 폐기했다.
- 구현 전 프로젝트 AGENTS.md와 해당 MSW 스킬·참조를 로드하고, 실제 파일을 다시 확인한다. 다른 에이전트의 변경을 이전 채팅 코드로 덮어쓰지 않는다.

## 읽기 전 핵심 요약

- Lv1~100 계정 레벨. 판 안 레벨과 분리하고 계정마다 영구 저장.
- 일반 보상은 만렙에 공격력·체력·방어력·최대 마나 각각 기본값 대비 +200%.
- 5레벨 특수 보상, 10레벨 주요 보상은 아래 정확한 표를 사용.
- 메인화면 **좌측 상단 프로필·프레임·닉네임**을 누르면 계정 정보 화면.
- 화면 **왼쪽 프로필·메뉴 고정 / 오른쪽 선택한 메뉴 내용**.
- 레벨별 효과는 **세로 스크롤 Lv1~100, 레벨 + 효과**. 일반 행 아이콘 없음. 5·10레벨 행에만 작은 표식.
- 적용 완료·미달성 문구, 현재 레벨 특별 강조, 누적 효과 버튼·요약, 가로 보상 로드맵은 넣지 않는다.
- Maker와 현재 FloorTable 모두 105층. EXP 상한 기준을 105층으로 통일한다. 계정 최대 레벨은 100이다.

## 1. 사용자 요청과 이번 문서의 해석

- 계정 레벨은 Lv1~100. 판 안 레벨과 별개이며 영구 저장한다.
- 층별 경험치를 차등 지급하고, 성공·실패에 따라 지급량을 구분한다.
- 일반 보상은 공격력·최대 체력·방어력·최대 마나만 사용한다.
- 5레벨 단위는 기존 게임의 특수 능력치, 10레벨 단위는 더 큰 특수 보상이다.
- 최신 요청: 일반 보상을 모두 모으면 약 3배 효과, 특수 보상은 직전 안의 2배 효율.
- **해석:** 일반 보상의 만렙 누적치는 각 능력치 기본값 대비 +200%(최종 3배). 특수 보상은 직전 표의 수치를 2배로 조정한다. 단순히 기존 일반 보상 숫자만 3배로 하는 의미가 아니다.
- **특수 보상 수치 2배와 실전 화력 2배는 다르다.** 발동·상한·합산·빌드에 따라 실제 효율은 달라지므로 밸런스 검증이 필요하다.

## 2. 일반 레벨 보상 — 전체 80회

| 끝자리 | 보상 | 횟수 | 만렙 누적 |
|---|---|---:|---:|
| 1·6 | 기본 공격력 +10% | 20회 | +200% |
| 2·7 | 기본 최대 체력 +10% | 20회 | +200% |
| 3·8 | 기본 방어력 +10% | 20회 | +200% |
| 4·9 | 기본 최대 마나 +10% | 20회 | +200% |

- 각 회차 증가량은 기준값의 10%를 합산한다. 레벨마다 1.1배씩 복리로 곱하지 않는다.
- Lv1에도 공격력 보상을 지급한다. Lv1부터 계산한 최종 누적은 기본값의 3배이며, Lv1 계정 대비 배율은 정확히 3배가 아니다.
- 최대 마나 기본값이 100이면 만렙 300. 마나 회복 속도·시작 마나는 자동 증가시키지 않는다.
- 계정 성장 적용 예: `계정 적용 기본 능력치 = 계정 보너스 제외 기본 능력치 × (1 + 계정 누적 증가율)`.
- 장비·각인·은총 등 다른 성장 항목까지 최종 3배가 된다는 뜻은 아니다. 구현 시 기본 능력치 산출 지점과 기존 보너스 합산 순서를 명시한다.
- 기본값이 0인 능력치는 비율 보너스만으로 증가하지 않는다. 모든 직업의 기본값을 확인한다.
- 계정 레벨 보상 때문에 판 안 카드·장비·빌드 선택이 무의미해지지 않도록 전투 테스트한다.

- 칭호·프로필 테두리는 선택적 기념 보상 제안이며 별도 확정 전 필수 보상으로 구현하지 않는다.

## 4. 1~100레벨 데이터 작성 규칙

1. 5의 배수는 §3의 특수 보상만 지급한다.
2. 나머지는 끝자리 기준 §2의 일반 보상을 지급한다.
3. 계정 초기 Lv1 보상을 포함하며, 중복 초기 지급을 방지한다.
4. 한 판에 여러 레벨이 오르면 지나간 모든 레벨의 효과를 반영한다.
5. 효과는 현재 계정 레벨과 보상 테이블에서 재산출하는 방식을 우선한다. 로그인할 때 다시 더해 능력치가 중복 증가하지 않도록 한다.

## 5. 층 경험치와 성공·실패 정산

현재 Maker·FloorTable의 **105층**을 EXP 곡선 끝점으로 사용한다. 한 판의 시작 층(StageStartFloor)을 기준으로 지급한다.

```text
클리어 EXP = 반올림(100 × 20^((min(105, 층 번호) − 1) / 104))
실패·중단 EXP = 내림(해당 층 클리어 EXP × 0.5 × 완료 스테이지 수 / 전체 스테이지 수)
```

| 시점 | 예상 도달 층 | 클리어 EXP |
|---|---:|---:|
| 시작 | 1 | 100 |
| 1주 | 20 | 173 |
| 1개월 | 35 | 266 |
| 3개월 | 55 | 474 |
| 반년 | 70 | 730 |
| 1년 | 80 | 973 |
| 2년 | 90 | 1,298 |
| 3년 | 100 | 1,732 |
| 현재 마지막 층 | 105 | 2,000 |

- 실패 시 아무 스테이지도 완료하지 못했으면 EXP 0.
- 별 미션과 계정 EXP는 분리한다. 별을 못 얻었다고 성공 EXP를 줄이지 않는다.
- 판 종료 시 서버에서 한 번만 정산한다. 결과창 재열기·중복 요청으로 추가 지급하지 않는다.
- 계정 EXP 획득량 증폭은 이번 레벨 보상에 포함하지 않는다.

## 6. 필요 경험치와 3년 기준

가정: 하루 20판, 성공률 80%, 실패 판 평균 진행도 50%. 위 도달 시점 사이의 층을 선형 보간하고 매일 당시 도달 층에서 플레이한다.

- Lv1→100 필요 총량: 약 **20,370,003 EXP**.
- Lv.L→L+1 필요량: `반올림((20,370,003 / 328,350) × L²)`, L=1~99.
- 실제 99개 필요량의 합계를 산출하고 마지막 단계에서 반올림 오차를 보정한다.
- 하루 20판·같은 도달 경로에서 약 1,095일. 매일 모든 판 성공하거나 상위층을 빨리 돌파하면 더 빨라진다.
- 강화된 보상이 실제 층 진행을 앞당길 수 있으므로, 3년은 보장 기간이 아닌 위 가정의 계산 목표다. 플레이 테스트 후 공급량·필요량을 함께 검증한다.

| 시점 | 예상 계정 레벨 |
|---|---:|
| 1주 | 약 9 |
| 1개월 | 약 17 |
| 3개월 | 약 28 |
| 반년 | 약 41 |
| 1년 | 약 58 |
| 2년 | 약 81 |
| 3년 | 100 |

계정 만렙은 장기 목표다. 일반 콘텐츠 대부분을 Lv100 달성 조건으로 잠그지 않는다. 무과금 1년 내 콘텐츠 80% 이상 경험이라는 게임 방향을 유지한다.

## 7. 최종 UI 구성 — 최신 사용자 피드백 반영

### 7.1 메인화면 진입 영역

- 위치: 좌측 상단. 프로필 초상 + 장착 프레임 + 계정 닉네임을 표시한다. 계정 레벨은 작은 배지로 병기 가능.
- 프로필 영역 전체를 클릭·터치할 수 있게 한다.
- 기존 입장 에너지 영역과 MSW 시스템 메뉴를 피해 배치한다. 에너지 아래 배치 또는 영역 재정렬은 실제 화면 확인 후 결정.
- 메인화면의 다른 버튼·팝업·스테이지 선택 화면을 침범하지 않도록 표시 조건과 레이어를 정한다.

### 7.2 계정 정보 공통 프레임

- 큰 제목은 정확히 **계정 정보**. `내 계정` 사용하지 않는다.
- 가로 1920×1080 기준. 좌측 약 28~30%, 우측 약 70~72%.
- 닫기 버튼 우측 상단. 원래 화면으로 돌아간다.
- 왼쪽은 고정: 장착 프레임 안의 프로필, 닉네임, 계정 Lv, 칭호, 세로 메뉴 5개.
- 메뉴는 `계정 정보`, `프로필`, `프레임`, `칭호`, `레벨별 효과`.
- 처음 열 때 계정 정보 탭을 선택한다. 다른 메뉴 클릭 시 오른쪽만 교체한다.

```text
┌──────────────────────────────────────────────────────────────┐
│                         계정 정보                       [X]  │
├──────────────────────┬───────────────────────────────────────┤
│ [프레임 안 프로필]   │ 선택한 메뉴 제목                      │
│ 닉네임               │                                       │
│ 계정 Lv.57           │ 메뉴별 상세 내용                      │
│ 장착 중인 칭호       │                                       │
│                      │                                       │
│ [계정 정보]          │                                       │
│ [프로필 바꾸기]      │                                       │
│ [프레임 바꾸기]      │                                       │
│ [칭호 바꾸기]        │                                       │
│ [레벨별 효과]        │                                       │
└──────────────────────┴───────────────────────────────────────┘
```

### 7.3 계정 정보 탭

오른쪽에 닉네임·계정 레벨·현재 레벨의 경험치 바와 수치를 표시한다.

- EXP 표기는 `현재 레벨 내 경험치 / 다음 레벨 필요 경험치`. 총 누적 EXP를 현재 레벨 진행도로 잘못 사용하지 않는다.
- 필요 시 다음 레벨의 추가 보상과 다음 5·10레벨 주요 보상을 간결하게 표시할 수 있다. 장식용 보상 수령 버튼은 넣지 않는다.
- 기본 진입 탭에서 현재 받고 있는 누적 능력치 전체를 나열하지 않는다.
- Lv100에서는 `MAX` 또는 `최고 레벨 달성`. 존재하지 않는 Lv101 필요 EXP를 표시하지 않는다.
- 닉네임 변경은 이번 범위에 없다. 표시용 계정 이름을 사용자 입력 변경 기능으로 확대하지 않는다.

### 7.4 프로필·프레임·칭호 변경 탭

공통 흐름: 오른쪽 목록에서 선택 → 왼쪽 프로필에 미리보기 → 오른쪽 적용 버튼 → 서버 확인 후 장착 상태 갱신.

- 프로필·프레임: 오른쪽 격자 목록, 스크롤 지원.
- 칭호: 오른쪽 텍스트 중심 세로 목록, 선택한 칭호의 획득 조건을 표시.
- 보유 항목은 원래 이미지·색상. 미보유 항목은 어둡게 표시하며 획득 조건을 볼 수 있다.
- 장착 항목은 작은 체크 또는 테두리로 구별 가능. `적용 완료` 같은 반복 상태 문구는 사용하지 않는다.
- 적용하지 않고 탭 이동·닫기 시 기존 장착 상태로 미리보기를 복원한다.
- 칭호는 적용·해제 지원. 프레임 해제 가능 여부는 기본 프레임 정책을 정한 후 처리.
- 프로필·프레임·칭호의 전체 목록 및 획득 경로는 미정이다. 임의로 유료 상품·과금 조건·업적 시스템을 추가하지 않는다.
- 제작용 예시 목록과 실서비스 카탈로그를 구분한다. 카탈로그가 없어도 로딩·빈 목록·기본 외형 상태를 지원한다.

### 7.5 레벨별 효과 탭 — 가장 중요한 시각 명세

오른쪽에 Lv1~100 전체를 세로 스크롤로 표시한다.

- 일반 행: **레벨 + 해당 레벨에서 추가되는 효과 텍스트만**. 공격력·체력·마나 등 개별 능력치 아이콘을 넣지 않는다.
- 끝자리 5: 보라색 작은 다이아몬드 같은 **특수 보상 표식 하나**와 보라 계열 프레임.
- 10의 배수: 금색 작은 왕관 같은 **주요 보상 표식 하나**와 금색 프레임.
- 두 종류의 표식은 구분 가능하게 한다. 상단에 작은 범례 `특수 보상 / 주요 보상`을 둘 수 있다.
- 보유 계정 레벨 이하 행: 정상 색상·원래 이미지 그대로.
- 미래 레벨 행: 채도를 낮추고 반투명 어두운 덮개로 잠긴 느낌. 효과 문구는 읽을 수 있게 유지한다.
- **적용 완료 / 미달성 등의 상태 문구와 행별 자물쇠 아이콘은 넣지 않는다.**
- **현재 레벨 별도 금색 강조·현재 레벨로 버튼·누적 효과 보기 버튼·현재 효과 합계 영역은 넣지 않는다.**
- 일반 행과 특수·주요 행의 보상 수치는 각각 §2·§3에서 가져온다. 이미지를 보고 숫자를 다시 입력하지 않는다.
- 여러 효과가 있는 행은 충분한 너비·높이를 확보한다. 두 줄 표시 가능. 한 줄에 억지로 넣어 폰트가 지나치게 작아지지 않게 한다.
- 기본은 전체 목록. 전체/주요 효과 필터는 필수 범위가 아니며 최신 이미지에는 필터 없이 범례만 있다.
- 목록은 오른쪽 영역 높이를 최대한 활용하고 스크롤바를 표시한다. 하단에 불필요한 큰 버튼을 만들지 않는다.

```text
레벨별 효과                 ◆ 특수 보상     ♛ 주요 보상

Lv.53     방어력 +10%                          정상 색상
Lv.54     최대 마나 +10%                       정상 색상
◆ Lv.55   치명타 확률 +2%p                    보라 프레임
Lv.56     공격력 +10%                          정상 색상
Lv.57     최대 체력 +10%                       정상 색상
Lv.58     방어력 +10%                          어두운 처리
Lv.59     최대 마나 +10%                       어두운 처리
♛ Lv.60   보스·엘리트 피해 +16%               금색 프레임 + 어두운 처리
          치명타 피해 +10%p
                           ↕ 스크롤
```

위 도식의 오른쪽 `정상 색상` 등은 제작 설명이며 실제 UI 문구가 아니다. ◆·♛는 최종 게임에서 실제 스프라이트로 대체한다. 최신 생성 이미지에서 Lv60 행이 밝게 보이더라도 **Lv57 계정의 미래 레벨은 금색 프레임을 유지하면서도 어둡게 처리**하는 규칙을 우선한다.

## 8. 결과창·스테이지 선택창 연결

### 결과창

- 계정 성장 블록: `획득 계정 EXP +N`, 경험치 바, 레벨 변화.
- 레벨업 시 새로 얻은 효과를 표시. 일반 레벨은 짧게, 5·10레벨은 강조.
- 복수 레벨 상승은 지나간 모든 보상을 적용하고 한 번의 연출로 요약.
- EXP0인 실패는 바 증가 연출 없이 0을 표시.
- 계정 EXP는 판 안 EXP·스킬북 등과 별도 라벨로 구분.
- 서버 정산 후 시각 연출만 실행. 연출 스킵·결과창 재열기로 보상을 재지급하지 않는다.

### 스테이지 선택창

- 상세 보상 영역에 `클리어 시 계정 EXP +N` 표시.
- 실패 보상은 완료 스테이지 비례라는 보조 설명.
- 에너지 입장 비용·별 미션·기존 전투 보상 규칙을 바꾸지 않는다.

## 9. 서버·저장·데이터 구현 계약

아래 이름은 의미를 설명하는 제안이며 기존 API가 실제로 있다고 가정하지 않는다.

| 데이터 | 필요 내용 |
|---|---|
| 계정 성장 저장 | 스키마 버전, 총 누적 계정 EXP, 필요 시 정산 중복 방지 정보 |
| 현재 성장 상태 | 계정 레벨, 레벨 내 EXP, 다음 필요량, 만렙 여부 |
| 정산 결과 | 판 ID, 층, 성공/실패/중단, 완료 스테이지, 획득 EXP, 이전/이후 레벨·EXP |
| 일반·특수 보상 데이터 | 레벨, 보상 구분, 효과 키, 값, 표시 단위·문구 |
| 꾸미기 데이터 | 보유 프로필·프레임·칭호 ID, 장착 ID, 항목별 리소스와 획득 조건 |

- 누적 EXP를 기준으로 레벨과 보너스를 재산출해 중복 효과를 방지한다.
- 계정 레벨을 닉네임이나 선택 프로필 ID에 묶지 않는다. 기존 플레이어 영구 ID를 사용한다.
- EXP 지급·레벨·소유권·장착 변경은 서버 검증. 클라이언트는 미리보기와 UI만 담당.
- 클라이언트에서 층·경험치·보상을 임의 전달해 확정하지 않는다. 실제 서버 판 결과 사용.
- 한 판이 여러 종료 경로를 타더라도 EXP는 한 번만 지급. 저장 실패 재시도와 결과창 재열기를 고려한다.
- 새 계정과 기존 계정의 첫 기능 도입은 Lv1·누적 EXP0 기본값. 과거 플레이에 대한 소급 지급은 별도 요청 전 하지 않는다.
- 불러오기 실패를 새 계정으로 취급해 빈 값으로 저장하지 않는다.
- 변동 때만 저장하고 매 프레임 EXP·프로필을 저장하지 않는다. 기존 저장 아키텍처와 MSW DataStorage 규칙을 따른다.
- 만렙 이후 화면은 MAX. 누적 EXP 보관·상한 정책은 구현 전에 명시하며 UI에 추가 성장 기능을 임의 제공하지 않는다.
- 카탈로그 ID가 삭제되거나 리소스가 없으면 안전한 기본 프로필·프레임으로 복원한다.
- 소유하지 않은 외형 장착 및 다른 계정 수정 요청을 서버에서 거절한다.

## 11. 인터랙션·연출·검증

- 계정창 진입은 짧은 페이드·소폭 확대, 메뉴 전환은 오른쪽 영역만 짧게 전환.
- 외형 미리보기는 왼쪽 프로필에 반영하되 실제 저장 상태와 구분. 빠른 연속 선택 시 마지막 선택 우선.
- 장착 저장 중 중복 클릭 방지, 성공 뒤 장착 표시 갱신, 실패 시 안내·복원.
- 리스트 여백·행 위에서 휠·드래그 입력 확인. 장식·배경이 가로채지 않게 하고 커스텀 휠·네이티브 스크롤의 중복 처리를 피한다.
- 모든 연결 이벤트·애니메이션 상태는 닫기·OnEndPlay에서 정리.
- 최소 터치 크기·모바일 가독성·우측 상단 플랫폼 UI 겹침 확인.
- 테스트: 신규/기존 계정, 성공/실패/중단, EXP0, 여러 레벨 상승, Lv5·10·100, 만렙, 재접속, 정산 재시도, 중복 지급 방지, 보너스 중복 적용 방지.
- 만렙 보너스 합계가 §2·§3과 일치하는지 확인. 최대 마나 증가가 회복 속도·시작 마나를 의도 없이 늘리지 않는지 확인.
- UI 테스트: 5개 탭, 미리보기 취소, 장착·해제, 빈 목록, 잠김 외형, 레벨1~100 스크롤, 일반 아이콘 없음, 5·10 표식, 미래 행 어둡게, 금지 문구·누적 효과 버튼 없음.
- Maker Refresh → 빌드 로그 → Play → 긍정 실행 로그로 검증. 정적 UI 작성만으로 실제 기능 완료라고 보고하지 않는다.
- 실제 입력 테스트가 안 되면 그 제한을 보고하고 API 위치 변경만으로 휠 조작감 검증을 대체하지 않는다.
