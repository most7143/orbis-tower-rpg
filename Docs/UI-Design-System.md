# 프로젝트 UI 디자인·구현 규칙

> 사용자 확정: 2026-11-17  
> 상태: 신규 UI와 기존 UI 개편에 적용하는 공통 기준  
> 기준 화면: 현재 프로젝트의 성장창 — 슬롯 강화 / 각인 / 심볼 / 은총 / 스킬

## 1. 적용 범위와 우선순위

앞으로 제작하는 모든 UI 및 기존 화면을 수정하는 작업은 이 문서를 먼저 읽고 따른다.

- 공통 골조는 **검정 외곽 + 흰색·밝은 회색 내부 영역**으로 통일한다.
- 메뉴·선택에는 **파랑**, 성장 실행·유리한 능력치 변화에는 **초록·연두**를 사용한다.
- 이전의 금색 프레임·보라색 패널 중심 테마보다 이 기준이 우선한다.
- 메인화면·직업선택 등 과거 시안은 콘텐츠와 배치 참고 자료로 사용할 수 있지만, 그 색상 테마를 새 UI의 기본값으로 가져오지 않는다.
- 직업색·등급색·아이템 색은 아이콘, 배지, 일러스트 등 필요한 부분에 제한적으로 사용할 수 있다.
- 화면별 기능과 배치는 유지한다. 테마 교체를 이유로 기능, 재화, 확률, 성장 수치, 저장 데이터를 변경하지 않는다.
- 기존 화면의 배치를 바꾸는 작업은 사용자가 요청한 범위에서 진행한다.

문서와 실제 구현이 다르면 최신 사용자 지시를 먼저 반영하고 문서도 갱신한다.

## 3. 색상과 투명도

| 역할 | 기준 |
|---|---|
| 외곽·헤더 | 검정에 가까운 차콜. 가는 중성 회색 테두리 |
| 본문 | 흰색·밝은 회색. 과도한 광택이나 두꺼운 장식 제거 |
| 내부 정보 묶음 | 본문보다 살짝 어두운 밝은 회색 면과 얇은 구분선 |
| 일반 글자 | 진한 회색: RGB(0.14, 0.17, 0.21) |
| 보조 글자 | 중간 회색: RGB(0.36, 0.40, 0.46) |
| 선택·탐색 | 파랑. 선택 탭·수량·카드·테두리에 사용 |
| 성장 실행 | 초록·연두. 강화·합성·은총 등 주요 실행 버튼 |
| 유리한 변화 | 읽기 쉬운 초록: RGB(0.20, 0.48, 0.12), 예: #347F24 |
| 부족·오류 | 읽기 쉬운 붉은색. 정상 수치까지 붉게 만들지 않는다 |

- 유리한 변화인지에 따라 색을 정한다. 피해 감소처럼 음수 표기여도 유리한 효과면 초록을 사용할 수 있다.
- 밝은 면에는 진한 글자, 어두운 면이나 채도가 있는 실행 버튼에는 흰 글자를 사용한다.
- 반투명 처리는 배경 면에 적용한다. 글자·아이콘까지 일괄 투명해지도록 처리하지 않는다.
- 현재 배경 PNG의 알파는 외곽 약 96%, 본문 약 97%, 내부 패널 약 92%다. 이는 출발점이며 실제 뒤쪽 화면과 겹쳐 확인한다.
- PNG 자체에 색과 알파가 있으므로 기본 렌더러 Color는 흰색·알파 1로 둔다. 불필요한 중복 틴트를 주지 않는다.
- 밝은 패널의 글자에 강한 검은 외곽선·그림자를 일괄 적용하지 않는다.
- 모든 칸을 각각 굵은 프레임으로 감싸지 않는다. 여백, 얇은 구분선, 면의 차이로 정보를 묶는다.

## 4. 탭과 내부 정렬

### 탭

- 탭은 본문 위에 붙어 있는 하나의 구성으로 보이게 한다.
- 선택 탭은 파랑과 흰 글자로 표시하고, 본문 상단의 가는 파란 연결선과 이어지게 한다.
- 비선택 탭은 차콜·회색 계열로 낮춰 표시한다.
- 탭 아래에 빈틈, 이중 테두리, 떠 있는 그림자가 생기지 않게 한다.
- 순간 호버·누름과 영구 선택을 구분한다. 클릭 후에도 현재 선택은 유지한다.

### 내부 정렬

- 각 패널의 제목·본문·목록·하단 실행 영역을 구분한다.
- 같은 정보 단위는 공통 부모 아래 묶는다.
- 반복되는 아이콘·항목명·수치·버튼은 같은 기준선과 간격으로 정렬한다.
- 글자와 버튼은 배경 안쪽 여백을 확보하고, 테두리 밖으로 튀어나오지 않게 한다.
- 1920×1080 기준으로 내부 큰 여백은 24~32px, 일반 컨트롤 간격은 12~16px부터 검토한다. 화면 크기와 실제 내용에 맞춰 조절한다.
- 긴 닉네임, 큰 수치, 여러 줄 설명, 미보유·최대 단계·재화 부족 상태도 확인한다.
- 크기를 바꿀 때는 글자와 터치 영역을 함께 점검한다. 이미지만 무리하게 늘리지 않는다.


### 메인화면 버튼·에너지 표시

- 보조 메뉴 3개는 같은 크기와 아이콘·글자 기준선을 사용한다. 현재 288×96, 아이콘 44×44, 글자 영역 176×44다.
- 가장 긴 메뉴명인 `스킬 뽑기`도 한 줄에 들어가는 폭을 확보한다. 글자만 줄이거나 줄바꿈으로 해결하지 않는다.
- 플레이 버튼은 448×128로 보조 메뉴보다 크게 표시한다.
- 우측 상단 에너지는 아이콘과 `현재/최대`, 충전 중일 때의 `분:초`만 표시한다. 입장 가능 횟수·충전 완료 문구는 생략하고 입장 비용은 스테이지 입장 버튼에서 안내한다.
- 에너지가 가득 차면 타이머를 숨기고 표시 높이를 96에서 64로 줄인다.
- 에너지는 우측 상단 기본 메뉴 예약 영역을 피한다. 현재 오른쪽 32px·위쪽 146px 위치를 사용하며, 기본 메뉴와 팝업의 조작부를 가리지 않아야 한다.
- 버튼의 RectSize 검사에 더해 실제 Maker 스크린샷으로 배경이 영역을 넘어 그려지지 않는지 확인한다.

## 5. 버튼과 공통 X 닫기

### 필수 상태

| 상황 | 필요한 이미지 |
|---|---|
| 모든 일반 버튼 | Normal / Hover / Pressed / Disabled |
| 선택이 유지되는 버튼 | 위 상태 + Selected |
| 선택 중에도 호버·누름이 있는 경우 | Selected Hover / Selected Pressed도 준비 |

- 각 상태는 같은 캔버스 크기, 피벗, 외곽 형태를 사용한다.
- 일반 버튼 글자는 이미지에 굽지 않고 인게임 텍스트로 넣는다.
- Disabled는 이미지 변경뿐 아니라 실제 입력도 차단한다.
- 선택을 해제하면 일반 상태의 호버·누름 이미지로 복구한다.
- 버튼 역할에 맞는 이미지 계열을 사용한다. 수량 버튼에 대형 장식 패널을 늘려 쓰지 않는다.

### 공통 닫기 버튼

- **단어 ‘닫기’ 없이 X만 표시한다.**
- 보이는 이미지 규격은 **64×64**, 모서리가 살짝 둥근 차콜 사각형, 가는 회색 테두리, 중앙의 흰 X다.
- 모든 창에서 동일한 close 이미지 계열을 재사용한다.
- X는 글자 폰트로 찍지 않고 공통 아이콘 이미지로 제공한다. 버튼의 텍스트는 비운다.
- Normal / Hover / Pressed / Disabled를 모두 사용한다.
- 창 우측 상단에서 일정한 안쪽 여백으로 배치한다.
- 모바일에서는 보이는 X의 크기를 유지하면서 터치 영역을 더 넓게 확보한다.
- 통합창 안의 하위 화면을 닫을 때 빈 본문만 남지 않도록 한다. 성장창에서는 공통 X가 현재 내용과 전체 성장창을 함께 닫는다.

## 6. 리소스 계열과 이미지 깨짐 방지

| 계열 | 용도 |
|---|---|
| button_* | 일반 버튼·수량·프리셋. 선택 시 파란 면과 흰 글자 |
| card_* | 정보 카드·목록·밝은 장비/스킬 칸. 선택 시 옅은 파란 면 |
| tab_* | 본문과 연결되는 탭 |
| action_* | 초록·연두 실행 버튼 |
| close_* | 공통 X 닫기 버튼 |
| panel_outer | 차콜 외곽 |
| panel_light | 밝은 본문 |
| panel_inner | 내부 정보 면 |
| outline_selected | 투명 바탕의 파란 선택 테두리 |
| slot_* | 기존 어두운 칸 계열. 현재 장비·스킬 장착 칸의 기본값으로 다시 사용하지 않는다 |

RUID는 manifest를 조회한다. 공통 상태 처리는 `UIButtonLogic.ThemeSkin(role)`과 `UseTheme(entity, role)`를 사용한다. 역할은 `button`, `card`, `tab`, `action`, `close`, `primary`다. 초기 공통 이미지로도 역할을 인식하며, 이후 런타임 갱신에서 예전 스킨으로 돌아가지 않도록 유지한다. 계정 외형 격자와 스테이지 가상 목록처럼 별도 상태 처리가 필요한 컨트롤은 같은 리소스 계열을 직접 사용한다. GrowthUILogic의 StyleButton은 성장창 경로에 한정된 분류 코드다.

- 패널·버튼은 리소스의 슬라이스 경계를 등록하고 Sliced로 표시한다. 배경 렌더러의 `PreserveSprite`는 **None(0)**으로 설정한다. AspectOnly가 남으면 지정한 RectSize보다 세로로 커져 다른 버튼을 가릴 수 있다.
- 현재 공통 패널·버튼 리소스의 경계는 좌·하·우·상 각각 12px다. close 이미지는 0px이며 Simple로 표시한다. 폭 16px 스크롤 손잡이는 전용 `thumb_*` 이미지와 3px 경계를 사용한다.
- 아이콘은 패널처럼 Sliced로 늘리지 않는다.
- 최소 컨트롤 크기보다 테두리 합이 커지지 않도록 한다. 작은 수량 버튼과 낮은 버튼에서도 위·아래 경계가 깨지지 않아야 한다.
- 새 리소스의 경계를 기존 값으로 추측하지 말고 실제 이미지에 맞게 설정한다.
- 접하는 패널 테두리를 중복으로 겹쳐 그리지 않는다.
- 실제 최소/최대 사용 크기와 모든 상태에서 모서리·테두리·피벗이 유지되는지 확인한다.

## 7. 아이콘의 형태·밝기·피벗

### 슬롯 강화

- 부위 아이콘은 **투구·옷·장갑·신발·망토·무기의 어두운 단색 실루엣**이다.
- 밝은 칸 배경 위에 실루엣을 표시한다.
- 이 화면에 실제 컬러 장비 그림이나 특정 장비의 썸네일을 다시 넣지 않는다.
- 선택 장비 미리보기도 같은 실루엣을 사용한다.
- 현재 틴트는 RGB(0.25, 0.29, 0.34), 알파 1이다. 회색 원본과 곱해져 어두운 실루엣으로 표시된다.
- 선택은 파란 테두리와 옅은 파란 배경으로 구분한다. 실루엣 색을 화려하게 바꾸지 않는다.
- 공용 장비 데이터나 실제 장비 외형까지 변경하지 않는다.

### 스킬

- 보유 스킬은 원래 색을 선명하게 표시한다.
- 미보유도 아이콘을 알아볼 수 있도록 현재 RGB 0.70 틴트·알파 1을 사용한다. 0.25 수준으로 지나치게 어둡게 만들지 않는다.
- 미보유 문구·빈 칸·실제 실행 버튼 상태로 보유 여부를 구분한다.
- 미보유 스킬의 상세 열람과 실제 강화·장착 가능 여부를 구분한다.
- 장착 칸은 밝은 배경과 파란 선택 표시를 사용한다.

### 중앙 정렬

- UI 아이콘의 피벗은 (0.5, 0.5), 렌더러 LocalPosition은 (0, 0), LocalScale은 (1, 1)을 기본으로 한다.
- 현재 스킬 아이콘은 **PreserveSpriteType.None**으로 표시한다. 원본 리소스의 피벗·위치를 따라가는 AspectOnly를 일괄 적용하지 않는다.
- 정사각형 스킬 아이콘은 고정된 UI 사각형 중앙에 표시한다.
- 비정사각형 아이콘은 컨테이너 안에 맞는 크기를 별도로 계산하되 중앙 기준을 유지한다. 비율 보존 때문에 위치가 치우치지 않는지 확인한다.
- 목록, 장착 칸, 패시브, 오른쪽 상세 미리보기 모두 같은 정렬 규칙을 적용한다.
- 런타임 이미지 교체·선택·탭 전환·갱신 후에도 설정이 유지되어야 한다.
- 다른 화면에서 avataritem 리소스를 사용할 때는 thumbnail:// 규칙을 따른다. 슬롯 강화는 위의 실루엣 규칙이 우선한다.

## 8. 구현·검증 절차

1. 이 문서와 해당 화면의 기능을 확인한다.
2. 기존 UI 트리·좌표·크기·바인딩을 확인하고 작업 전 값을 깊은 복사로 보관한다.
3. 기존 공통 리소스를 우선 재사용하고, 필요한 경우에만 같은 규격의 새 리소스를 만든다.
4. .ui의 읽기와 수정은 UIBuilder를 사용한다. 원본 JSON을 직접 패치하지 않는다.
5. 정적 UI와 런타임 스킨·색상·이미지 교체 코드를 함께 수정한다.
6. 버튼은 초기화 때 스킨을 준비한다. 창을 열 때마다 전체 UI 스킨을 불필요하게 다시 입히지 않는다.
7. UI 린트와 배치 비교로 의도하지 않은 변경을 확인한다.
8. Maker Refresh → 빌드 로그 → Play → 실제 표시/선택/갱신 경로와 실행 로그를 검증한다.
9. 선택 유지, 재화 부족, 미보유, 최대 단계, 닫기, 탭 전환, 비활성 입력 차단을 확인한다.
10. 리소스를 추가·교체했다면 해당 manifest와 이 문서의 영향을 받는 항목을 갱신한다.

## 9. 기존 화면 전환 범위

성장창 5종에 이어 다음 화면의 정적 리소스와 런타임 상태 처리를 공통 테마로 전환했다.

- 메인화면과 스테이지 선택: LobbyUI
- 계정 정보: AccountUI
- 인게임 HUD와 정보·직업·장비·스킬 패널: BattleHUD, MainPanel
- 일반 안내와 확인: PopupGroup, ConfirmUI
- 직업·스킬 카드 선택: TarotUI
- 거래 선택과 결과: DealUI, ResultPopup
- 스킬 소환과 테스트: GachaUI, SkillTestUI

기존 배치는 유지하되 공통 X 규격 적용과 계정·소환창 헤더의 영역 초과를 해소하는 최소 조정만 했다. 직업 일러스트, 스킬·아이템 아이콘, 외형 프레임·칭호, HP/MP 등 의미를 가진 색상은 보존한다. 직업 카드의 일러스트는 별도 마스크 영역 안에 표시하고, 스킬 카드의 종류는 텍스트로 구분한다.

MainPanel과 SkillTestUI의 스크롤 목록에는 뷰포트 밖에 배치된 기존 행이 있다. UI 린트의 L013 중 실제 ScrollLayoutGroup 내부 행에 한정된 항목은 스크롤 콘텐츠로 확인했으며, 이를 지우기 위해 행 좌표나 목록 구조를 바꾸지 않는다.


## 10. 여신의 제안과 효과 툴팁 (2026-11-21)

- 보스 보상의 거래창을 `여신의 제안`으로 표시한다. 축복의 여신은 대가 없는 효과, 계약의 여신은 이득과 대가를 같은 대상에게 준다. 화면은 제안 이름·대상·효과·기간을 표시한다. 여신 구분 제목과 얻는 효과/치르는 대가 라벨은 생략하고 이득은 녹색, 불이익은 붉은색 수치로 구분한다. 효과마다 별도 박스를 두지 않는다. 이 화면 글자는 Default 글꼴, FaceDilate 0, 외곽선·그림자 없이 표시한다.
- 대상은 제안을 생성하는 서버에서 파티 전체 또는 생존 중 무작위 1명으로 정하고 선택 전 공개한다. 다시 표시해도 대상은 바뀌지 않는다. 현재 단일 대상 추첨 확률은 50%, 단일 대상의 유리한 수치는 원래 값의 1.5배다. `GoddessSingleChance` / `GoddessSingleScale`로 조정한다.
- 메소와 추가 카드 보상은 파티 공유다. 즉시 회복은 쓰러진 대상을 부활시키지 않는다. 체력 대가는 생존자의 현재 체력 기준이며 1 미만으로 내리지 않는다. 최대 체력 효과도 쓰러진 캐릭터를 부활시키지 않는다.
- 지속 효과는 발생 건별로 보관하고 같은 능력치는 합산한다. 개별 캐릭터의 공격·크리티컬·방어·체력·공격 간격·받는 피해에 해당 대상 효과만 적용한다. 기존 보상표 수치는 유지한다.
- 기간 제한 효과는 이후 웨이브 클리어마다 감소한다. 제한 없는 효과는 이번 판 동안 유지한다. 새 판 시작 시 초기화한다. 즉시 회복·메소 지급·카드 지급은 지속 효과 목록에 넣지 않는다.
- 맵 이름 아래 좋은 효과·나쁜 효과 아이콘 두 개를 64×64로 표시하고 터치 영역은 88×88로 둔다. 숫자는 효과 건수다. PC 호버로 열고 모바일 터치로 고정·해제하며 바깥 터치로 닫는다. 목록은 동적 높이(128~560)와 세로 스크롤을 사용한다. 보상창 등 모달 상태에서는 감춘다.
- 버프 `17a36caba3194b2c8ba794336503a326`, 디버프 `8c49fdffcf2c41dcad72eee778ef5396`. 툴팁은 `aa92764c33bc49c49217895275b58d0e`, 256×144, 슬라이스 좌5·하12·우5·상12, PreserveSprite=None이다. 내부는 불투명 검정, 글자는 흰색이며 효과 수치만 녹색·붉은색으로 구분한다. 위쪽 흰 헤더가 있는 이전 이미지는 사용하지 않는다.
- 구현: `TowerRunManager`, 각 직업 Combat, `DealUILogic` / `DealUI`, `GoddessStatusUILogic` / `GoddessStatusUI`. 리소스는 `output/ui/status_icons/`, `output/ui/status_tooltip/manifest.json`을 따른다. 버튼은 공통 action/button 4상태를 재사용한다.
