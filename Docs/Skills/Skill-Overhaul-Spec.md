## 1. 원본 데이터 상황 (구현 전에 꼭 읽기)

1. **원본 수치 XML이 없다.** `최신메이플데이터/Skill/Skill.xml` 은 `Dragon`·`MobSkill` 폴더 목록뿐이고, 직업별 스킬 XML(`Skill/112.img` 등: damage·attackCount·mobCount·cooltime·elemAttr 레벨별 값)이 외장 SSD와 그 압축본 어디에도 없다. 그래서 JSON의 `values`는 모두 `null`이고, 대신
   - `h` : 원본 설명 문자열 (`#damage`, `#attackCount` 같은 변수 자리 포함),
   - `vars` : 그 스킬이 원본에서 쓰는 수치 변수 이름,
   - `gameRef` : 같은 이름 스킬이 지금 게임(`JobSkillTable`)에 있으면 그 값(계수%·타수·쿨타임)을 적었다.
   - 원본 수치가 꼭 필요하면 사용자에게 `Skill/<직업>.img` XML 추출본을 요청해야 한다 (예전 `~/Downloads` 폴더는 기준이 아니어서 쓰지 않았다).
2. **원본 elemAttr 를 읽을 수 없어** 속성은 스킬 성격(설명·이펙트)으로 붙였다 (5절).
3. **아이콘 없는 원본 16개**: 나이트로드 410·411·412, 바이퍼 510·511·512의 공격 스킬 다수는 폴더에 `effect`·`hit`만 있고 `icon.png`가 없다 (추출 때 링크 그림이 빠진 것으로 보임). 쿼드러플 스로우(4121013)는 이름표에만 있고 그림 폴더 자체가 없다.
4. 최신 데이터 기준이라 **지금 게임에 있는 일부 스킬 이름이 원본 해당 직업에 없다** (6절 목록). 개편 때 원본 스킬로 바꾼다.

### 2-2. 전투에서 스킬이 쓰이는 방식
- 전투 컴포넌트: 히어로 `Tower/HeroCombat.mlua`, 비숍 `Tower/BishopCombat.mlua`, 나머지 3직업 `Tower/JobCombat.mlua`. 판 시작 때 `ApplySlots`가 그 캐릭터 차수의 칸 스킬을 장착한다.
- **자동 시전** (`JobCombat.RollCasts` → `PickActed`): 기본 공격 1회마다 마나·궁극기 게이지를 채운 뒤, 동작 있는 스킬 1개를 고른다. 순서: ① 궁극기(게이지 가득, `TryUltCast`) → ② 쿨타임형(`Trigger=Cooldown`, 하이퍼 포함) → ③ 마나형(`Trigger=Skill`, 쿨이 끝났고 마나가 되는 것 중 비용 큰 것). 사거리 밖이면 `RollFreeCasts`가 궁극기·쿨타임형만 시전. Auto형(쉐도우 파트너 등)은 `TickAuto`, Instinct형은 기본 공격 적중 시 확률 발동.
- **쿨타임**: `JobSkillTable.Cooldown` (칸 표 `CdSec`가 있으면 덮어씀), `self._T.cd[스킬ID]`로 관리.
- **피해 계산**: `JobCombat.Strike` (히어로·비숍도 같은 구조) = `ActorHitDamage × 계수% × 칸 배율(PctMul) × (1+별 위력+보너스) × (1+자원 공격력) × (1+방어 감소) × (1+망토 칸 피해) × (1+스킬 피해)` → 치명타. 실제 적용은 `DealTo` → `TowerRunManager.ApplyRolledDamage`/`ApplySplashDamage`. 속성은 `TowerRunManager` 4269행 부근에서 `Element`가 있으면(출혈 제외) 유물 `ElemDmg` 보너스 대상.
- **물리/마법 구분은 지금 없다.** 모두 `ActorHitDamage` 하나로 계산한다 → 다른 담당자의 "물리/마법 + 속성 약점/반감 + 명중/회피" 설계에 연결할 자리.
- **스킬 ID별 특수 코드가 많다** (예: `JobCombat`의 `N04` 쉐도우 파트너, `A12` 퀴버 풀버스트, `N15` 비전서, `V10` 스티뮬레이트 분기). 새 스킬을 옛 ID에 넣으면 옛 특수 동작이 따라오므로 주의 (9절).

### 2-3. 캐릭터 화면
- `Character/CharacterUILogic.mlua` 778행 `keys = { "Passive", "Main", "Sub", "Tech", "Hyper", "Ult" }` 6칸. 칸 정보는 `CharSlotTable`+`CharSkillSlotTable`+`CharPassiveTable`에서 읽는다. 캐릭터 화면 UI 파일(`ui/CharacterUI`)에 칸 6개.

## 3. 차수 규칙 적용안

| 차수 | 레벨 | 칸에 들어가는 원본 | 누적 여부 |
|---|---|---|---|
| 1차 | 1~ | 1차 공격 1개 (주력기) + 고유 패시브 | — |
| 2차 | 7~ | 2차 공격 1(주력기) + 2차 1(보조기) | **비누적**: 1차 스킬은 2차 스킬로 교체 |
| 3차 | 13~ | 3차 3개 (주력기·보조기·기술) | **비누적** |
| 4차 | 19~ | 4차 3개 (주력기·보조기·기술) + **하이퍼 액티브 1(하이퍼 칸)**. 공격형 하이퍼 액티브는 기술 칸에도 씀 | **비누적** (3차 → 4차 교체) |
| 5차 | 25~30 | 4차 칸 4개 **유지** + **5차 직업 고유 스킬 4개 전부** (궁극기 1 + 5차 칸 3) | **누적** (4차 유지) |
| 각성 | 30~40 | 각성 1~5단계마다 한 칸씩 **6차 VI 스킬로 강화**: 주력기 → 보조기 → 기술 → 하이퍼 → 궁극기(오리진 스킬) | 같은 스킬의 강화판으로 교체 |

- 2·3차를 비누적으로 한 이유: 지금 칸 구조가 "칸 안 스킬이 진화"하는 방식이라 그대로 맞고, 원본에서도 1~3차 공격기는 상위 차수 공격기로 대체된다. 칸 수가 늘지 않아 UI·돌파 연결이 단순하다. 판 안 돌파는 칸에 붙어 있으므로 진화해도 이어진다(기존 규칙 유지).
- 5차를 누적으로 한 이유: 각성이 "4차 스킬을 강화"하므로 5차에서도 4차 스킬이 칸에 남아 있어야 한다.
- 각성에서 VI가 없는 칸: 보우마스터 보조기(샤프 아이즈) → 6차 신규 `엑스트라 퀴버 카트리지`, 바이퍼 하이퍼(스티뮬레이트) → 6차 신규 `헤이메이커`로 교체안 (사용자 확인 필요).
- 흡수·제외: 버프 패시브·숙련도류는 **고유 패시브 차수 효과**(`CharPassiveTable` Extra)로 흡수. 하이퍼 패시브(…-리인포스 등)는 해당 칸 위력 보정(`CharSkillSlotTable.PctMul`)으로 흡수. 이동기는 제외. 직업군 공용 5차(오라 웨폰, 오버로드 마나, 레디 투 다이 등)와 모험가 공용(메이플월드 여신의 축복)은 **제외**(직업 고유가 아님) — 필요하면 장신구·유물 효과 후보.

## 4. 칸 구조 제안

### B안 (추천) — 9칸
`고유 패시브 · 주력기 · 보조기 · 기술 · 하이퍼 · 5차 칸1 · 5차 칸2 · 5차 칸3 · 궁극기`
- 근거: "5차는 5차 스킬 전부"를 그대로 지킬 수 있다(직업 고유 5차 4개). 4차 칸 유지 → 각성(4차 VI) 규칙과 맞물린다. 5차 칸 3개는 5차에만 열리므로 1~4차 화면은 지금과 같다.
- 5차 칸 자동 시전: 공격기는 쿨타임형(`Trigger=Cooldown`, 쿨 12~25초), 버프는 Auto형. 공격 1회에 동작 스킬 1개만 나가는 지금 규칙(`PickActed`) 때문에 칸이 늘어도 시전 밀도는 크게 오르지 않는다 → 밸런스는 `CharSkillSlotTable.PctMul`로 조정.
- 비용: 캐릭터 화면 UI에 칸 3개 추가, HUD 스킬 칸 3개 추가, 돌파 풀 3칸분 추가(`SkillBreakTable`).

### A안 — 6칸 유지
- 5차: 궁극기 = 5차 대표 1개, 나머지 5차 3개는 **기술 칸 진화(공격 1)** + **보조기 칸 진화(버프 1)** + **고유 패시브 흡수(1)**.
- 장점: UI·HUD·돌파 수정 최소. 단점: 5차에 4차 기술·보조기가 사라져 각성(4차 VI) 대상이 줄고, "5차 스킬 전부" 규칙이 패시브 흡수로 약해진다.

### 공통
- 각성 5단계 = 주력기·보조기·기술·하이퍼·궁극기 (기준 문서 "5개 스킬이 하나씩" 유지). B안의 5차 칸 3개는 각성 대상이 아니다 (원본 6차 "○○ 강화" 코어는 5차 칸 위력 보정 후보).

## 5. 물리/마법 · 속성 태그

- **물리/마법**: 히어로·나이트로드·보우마스터·바이퍼 = `물리`, 비숍 = `마법`. JSON `damageType`에 스킬 단위로 넣었다.
- **속성** (`element`): `불 / 얼음 / 번개 / 독 / 성 / 어둠 / 무` 중 하나. 원본 elemAttr를 읽을 수 없어 스킬 성격으로 정했다.
  - 비숍: 전부 `성` (에너지 볼트는 원본상 기초 마법이나 비숍 통일로 성 제안).
  - 히어로: 무, 소드 오브 버닝 소울만 `불`.
  - 나이트로드: 표창 공격 무, 쉐도우 파트너·다크 플레어·다크로드의 비전서·생사여탈 `어둠`, 스로우 블래스팅(폭발 부적) `불`. 베놈·블리딩 톡신(패시브 흡수)은 `독` 지속 피해.
  - 보우마스터: 무, 피닉스·퀴버 풀버스트(화염 화살) `불`.
  - 바이퍼: 무, 라이트닝 폼 `번개`. 수룡(씨 서펜트 계열)은 물 성격이지만 목록에 물이 없어 `무` — 물 속성 추가 여부는 전투 담당과 협의.
- 지금 `JobSkillTable.Element` 값(`불`·`얼음`·`신성`·`출혈`)과 표기가 다르다: `신성`→`성` 통일 또는 대응표. `출혈`은 속성이 아니라 상태 이상으로 분리 권장.

## 8. 아이콘 준비 현황

- 방법: 스킬 이름으로 `msw_resource_api.cjs search "<이름>" --resource-type sprite --category skill --topK 5` 결과 + 지금 게임 같은 이름 RUID를 후보로, 원본 `icon.png`와 MSW 썸네일을 32×32로 맞춰 픽셀 차이를 비교(26 미만) → 미리보기 이미지로 육안 확인.
- 결과: **RUID 18개** (주로 5차 — MSW에 최신 5차 아이콘이 있음), **업로드 필요 61개** (1~4차·6차: MSW에는 옛 버전 아이콘만 있어 최신 원본과 그림이 다름), **원본 그림 없음 16개** (나이트로드·바이퍼 2~4차 — JSON `mswCandidateUnverified`에 지금 게임 RUID나 검색 1순위를 참고용으로만 넣었다. 원본과 대조하지 못했으니 그대로 쓰지 말 것).
- 업로드: 원본 `icon.png`(32×32)를 `msw-mcp` 자원 업로드로 올리고, 받은 RUID를 JSON `mswRuid`와 `JobSkillTable.IconRUID`에 넣는다. 스킬 아이콘 표시 기준(UI 칸 중앙, PreserveSpriteType.None, 피벗 0.5/0.5)은 `Docs/UI-Design-System.md`를 따른다.
- 미리보기: `output/preview/skill_overhaul_icons.png` (왼쪽 원본 4배, 오른쪽 MSW 최근접 썸네일 4배, 초록=같음·빨강=업로드 필요·회색=원본 없음).

## 9. 구현 시 바꿀 파일과 순서

> 다른 세션이 `CharacterUILogic.mlua`, 캐릭터 화면 UI 파일, `TooltipLogic.mlua`, `PlayerEngrave.mlua`를 고치는 중(커밋 전)이다. 시작 전에 최신 내용을 다시 읽고 덮어쓰지 말 것.

1. **사용자 확정**: 칸 구조(B안/A안), 차수별 선택 스킬, 각성 VI 없는 칸 교체안, 속성 표기(성/신성, 물 속성 여부).
2. **아이콘**: 업로드 필요 61개 업로드, 원본 없는 16개는 사용자에게 원본 그림 요청 또는 옛 아이콘 사용 허락 → JSON `mswRuid` 채우기.
3. **`JobSkillTable.csv`**: 새 스킬 행 추가. 내부 ID는 새 번호(예: 히어로 `H20~`)로 만들고, 기존 ID의 특수 코드(`N04`, `A12`, `V10` 등)를 계속 쓸 스킬만 기존 ID를 재사용한다. 열 추가 제안: `OriginalId`(원본 ID), `DamageType`(물리/마법), `Element` 값 통일. 수치는 `gameRef`와 역할로 정한다 (원본 수치 없음).
4. **`SkillActionTable.csv`**: 새 스킬 연출(동작·이펙트·소리). 원본 이펙트 그림은 `_Canvas/<직업>.img/skill/<ID>/effect`·`hit`에 있다 (이펙트 RUID 검색은 별도 작업).
5. **`CharSlotTable.csv`**: 칸별 T1~T5 스킬 ID 교체. B안이면 `V1`·`V2`·`V3` 행 추가(T5만 채움). 각성용 열 `A1~A5`(또는 새 표 `CharAwakenSkillTable.csv`: JobId, Stage, SlotKey, SkillId) 추가.
6. **`CharSkillSlotTable.csv`**: 새 칸·차수 행 (PctMul·CdSec·TriggerAs). 하이퍼 패시브 흡수분을 PctMul로.

## 10. 확인 못 한 점

- 원본 레벨별 수치(damage·attackCount·mobCount·cooltime)와 elemAttr: SSD에 직업별 스킬 XML이 없음.
- 원본 그림 없는 16개 스킬의 정확한 아이콘.
- 5차 스킬의 직업 소속은 원본에 직업 표기(V코어 데이터)가 없어 설명 내용(콤보·성수·표창·화살·수룡 언급)과 메이플 지식으로 판별했다.
- 게임 안 동작·밸런스는 확인하지 않았다 (설계 단계, 메이커 미사용).
