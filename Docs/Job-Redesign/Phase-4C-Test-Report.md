### 2-1. 측정 방법

- 5차(Lv25) 편성, `DebugGod(true)`, 판 자동 진행. 0.25초마다 서버에서 구성원별 `UltGauge`(오른 양 합 = 충전량, 내려가면 궁극기 1회), `mgr:CanReach(구성원, 맨 앞 몬스터)`, `Mana`, 스킬 쿨타임(`_T.cd`가 다시 올라가면 시전 1회)을 기록.

### 2-3. 원인 (코드 추적, `Tower/TowerRunManager.mlua`)

1. **닿지 않으면 아무것도 안 한다** — `ActorTryAttack`(5800행) 첫 줄 `if self:ActorBusy(actor) or not self:CanReach(actor, monster) then return timer end`. 기본 공격(`ActorAttack` → `RollJobProcs` → `hero:RollCasts`, 게이지 +4)도, 따로 시전(`hero:RollSkillCasts` → `PickActed`, 게이지 +6)도, 쿨타임형 자기 버프·하이퍼(H10 발할라·H11 에픽 어드벤쳐·H05·B11·B10)도, **가득 찬 궁극기**(`PickActed` 맨 앞)도 모두 이 뒤에 있다. 직업 공용 `JobCombat.TickAuto`(Auto형 V10·N04 등)만 사거리와 무관하게 돌아 바이퍼가 히어로보다 조금 높다.
2. **사거리 칸** — `CanReach`(5765행) = `CellAt(몬스터 x) <= ActorRange(actor)`, `JobRanges = "Hero:1,Viper:1,Bishop:2,NightLord:2,Bowmaster:3"`(453행, RunConfig에 없음).
3. **몬스터가 2칸에 멈춘다** — 맨 앞 몬스터의 목표 칸 = `MonRange(mc)`(5756행): 데이터 `AttackRange`(1·2), 웨이브 원거리 자리(`RangedRatio 0.34`)는 최소 2칸. 다음 맨 앞은 사거리 짧은 몬스터부터 나오지만(3255행) 원거리 대기열은 결국 2칸에서 싸운다.
4. **당겨 오기 조건이 근접을 버린다** — `PullIfUnreachable`(5772행)은 "살아 있는 우리 편 **누구도** 닿지 않을 때만" 1칸으로 당긴다. 비숍·나이트로드·보우마스터가 있으면 항상 누군가 닿으므로 **2칸 몬스터는 죽을 때까지 2칸**, 근접은 그동안 0회 행동. 실측 로그 `front monster unreachable` 0건.
5. **1칸 몬스터도 오는 길에 죽는다** — 2칸→1칸 이동(1칸 / 1.5 = 0.67초) 중 원거리 구성원에게 처치. 저층·고차수일수록 심함(1층 히어로 닿음 0%).
6. **충전원이 행동뿐** — 기본 공격 간격 `AttackCooldown 3 / WeaponSpeed`(약 2.7초)마다 +4, 스킬 시전마다 +6. 모두 닿는 실험에서도 실제 시간 1.5~1.6/초 = 약 57초. 판의 비전투 시간(스테이지 전환, 처치 사이)에는 0.
7. **마나 조건은 원인이 아니다** — 히어로 마나 평균 93~95, 120초 중 35~46초 가득. H08 쿨 4.8초도 막지 않는다(닿을 때 5.5~6초 간격).

### 2-4. 4-G 수정안 (목표: 궁극기 약 30초)

순서대로 적용을 권장한다. A가 근접 문제, B가 주기 문제다.

- **A. 근접이 닿게 하기** (택1)
  - A1(권장): `PullIfUnreachable` 조건을 "누구도 닿지 않음" → "**살아 있는 구성원 중 닿지 않는 사람이 있고 그 상태가 N초(예: `PullDelay` 1.5초, RunConfig) 이상**"으로. 원거리 몬스터도 1칸에서 계속 원거리 공격하면 되므로 몬스터 공격 규칙은 그대로다. 모두 닿게 한 실험에서 히어로 H08 5.5~6초 간격, 게이지 1.62/초(원거리와 같은 수준)로 회복.
  - A2(데이터만): `JobRanges`를 RunConfig로 빼고 `Hero:2,Viper:2`. 2칸 몬스터는 닿지만 3칸(보우마스터 전용 거리) 개념이 약해진다.
- **B. 게이지 주기 맞추기** (A 적용 뒤 실측 1.5~1.8/초 기준)
  - B1(데이터만, 권장): `UltGaugeMax 100 → 55` 또는 `UltGaugeBasic 4 → 7`·`UltGaugeSkill 6 → 11`. 1.6/초 × 1.8배 ≈ 3/초 → 약 33초.
  - B2(코드): 전투 중 시간 충전 `UltGaugePerSec`(RunConfig, 예 1.5) 추가 → 사거리·직업 차이를 줄인다. "전투 시간 30초" 기준이라면 B2만으로 충분.
  - B3(선택, 템포): `SpawnOffsetX 6 → 4` 또는 `MonsterWalkSpeed 1.5 → 2.2`로 걸어오는 시간을 줄이면 모든 직업의 실제 시간 효율이 오른다(전투 중 비닿음 59%의 대부분이 걸어오는 시간).
- **C. 사거리와 무관해야 할 시전 분리** (코드): `ActorTryAttack`에서 `CanReach` 검사 전에 ① 게이지 가득 찬 궁극기(화면 전체기), ② 쿨타임형 자기 버프·하이퍼(`slotOf == "Hyper"` 또는 `HasAction == false`인 버프)는 닿지 않아도 시전. T24 기대("다음 시전 차례에 세 구성원 모두")가 지금은 히어로에서 성립하지 않는다.
- 기준 정리 필요: 마스터 스펙·문서 C11의 "약 30초"가 **실제 시간**인지 **전투 시간**인지(6절 질문 1).

## 4. 버그

### B1. 근접 구성원이 원거리 동료와 함께면 거의 행동하지 못함 (중대, 4-C·4-D 핵심 기능에 영향)
- 재현: 히어로 또는 바이퍼 + 비숍/나이트로드/보우마스터 편성, 5차, 30층 120초.
- 결과: 근접 닿음 3~6%, 궁극기 0회, H08 2~3회/분, 하이퍼 발할라 120초에 1회, 마나 가득인 채 대기.
- 원인: `TowerRunManager.ActorTryAttack`의 `CanReach` 조기 반환 + `PullIfUnreachable`의 "누구도 닿지 않을 때만" 조건 + `MonRange` 원거리 최소 2칸. 수정안 2-4 A·C.

### B2. 궁극기 주기가 목표(약 30초)의 2배 (중간, 밸런스)
- 원거리도 실제 시간 55~60초. 원인·수정안 2-3·2-4 B.

### B3. 디버그로 높은 층에서 지면 계정 최고 층이 그 층으로 저장됨 (테스트 도구 주의)
- `DebugStartFloor(90)` 후 패배 → `Defeat`가 `BestFloor = Floor(90)`로 바꾸고 `SaveBestFloor` 저장(`best floor saved=90`). 정상 판은 열린 층만 시작하므로 게임 버그는 아니지만, 최고 층이 장비 칸 해금(`UnlockBestFloor`) 등에 쓰여 테스트가 계정을 바꾼다. 이번 테스트는 바로 `{"best":20}`으로 되돌림(10절). 문서 8-1에 "높은 층 패배 테스트 뒤 최고 층 복원" 또는 `DebugStartFloor` 판은 최고 층을 저장하지 않게 하는 것을 권장.

## 5. UI 이상

## 6. 자료 조사 에이전트에게 넘길 질문

1. 궁극기 "약 30초"는 **실제 시간**인가, **전투 시간**인가? 전투 시간이면 원거리는 이미 25~29초이고 근접(B1)만 고치면 된다. 실제 시간이면 2-4 B까지 필요.
2. 근접 해결을 **당겨 오기 규칙 변경(A1)** 으로 할지 **사거리 데이터(A2)** 로 할지. A1이면 대기 시간 `PullDelay` 값.
3. 궁극기·쿨타임형 버프·하이퍼를 **사거리와 무관하게** 시전할지(C). 발할라·에픽 어드벤쳐·인레이지·어드밴스드 블레스는 자기 버프라 닿지 않아도 써지는 것이 자연스럽다.
4. 하이퍼 "쿨 40초"에 계정 쿨 감소(지금 4%)를 적용하는 것이 맞는지(지금 38.4초).
5. `DebugStartFloor` 판의 패배가 최고 층을 저장하지 않게 할지(B3).
