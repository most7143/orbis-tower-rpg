## 2. 검증 결과 상세 (4-D 보완 · 4-E · 4-F)

### 2-1. 차수별 패시브 레벨·숨은 장착·강화 (T26·T27·T29·T30)

`DebugSetChar(직업,1,시작레벨,차수)` → `DebugStartFloor(1)` 후 서버에서 각 전투 컴포넌트를 직접 읽음.

| 차수 | 히어로 | 비숍 | 나이트로드 | 보우마스터 | 바이퍼 |
|---|---|---|---|---|---|
| 1 | pl=1, 숨은 없음 | 1, 없음 | 1, 없음 | 1, 없음 | 1, 없음 |
| 2 | 3, 없음 | 3, 없음 | 3, 없음 | 3, 없음 | 3, 없음 |
| 3 | 5, H15 | 5, B12 | 5, N13 | 5, A13 | 5, V13 |
| 4 | 7, H15 + ComboCap10 | 7, B12·B04 | 7, N13·N09 | 7, A13·A09 | 7, V13·V09 |
| 5 | 9, H15 + ComboCap10·ComboGain50 | 9, B12·B04 + HolyMax10 | 9, N13·N09 + ResMax8 | 9, A13·A09 + ResMax15 | 9, V13·V09 + EnergyPlus3 |

- 장착 순서: 칸 스킬(주력·보조·기술·하이퍼·궁극기) 다음에 숨은 스킬. 예) 5차 비숍 `B06,B09,B15,B10,B13,B12,B04`.
- T29 함수 값: 히어로 `ComboCap()=10`, 비숍 `HolyMax()=10`, 나이트로드 `CalcResMax()=8`, 보우마스터 `CalcResMax()=15`, 바이퍼 `EnergyPerHitNow()=8`.
- HUD: 5차 A·V·H 판 client `P1~P3/S1~S5` 아이콘 켜짐, S6 없음 → 숨은 스킬은 칸에 안 나옴.
- T27 발동(3차, 무적, 각 40초): `passive proc job=Hero id=H15` 4회, `Bishop id=B12` 2회, `NightLord id=N13` 1회, `Viper id=V13` 1회, **`Bowmaster id=A13` 0회**. A13 발동 경로는 N13·V13과 같은 `JobCombat` Instinct 분기라 확률(10%) 탓으로 보지만 로그로 확인하지 못했다.

### 2-2. 위기 자동 (T28)

무적 끄고 25층 4차. 메인 체력을 최대의 35%로, 바이퍼(동료 2)도 35%로.

### 2-3. 돌파 칸 연결 (T31·T32·T33)

- T31: 2차 히어로 판 `DebugGiveBreaks("H02_B1")` → `HeroBreak("H02","H02_B1") = true`, 키 `Hero.Main#1`.
- T32: `DebugSwapSlot("Hero","Main","H08")` → 히어로 장착 `H08,H05`, `HeroBreak("H08","H08_B1") = true`, `BreakKey("H08") = Hero.Main`, 남은 목록 `H08_B2,H08_B3,H08_B5`(B1 빠짐). 이어서 `H08_B2,H08_B3` 지급 → `BreakCountFor("H08") = 3`, 남은 목록 비어 있음(히어로식 최대 3개를 칸 기준으로 셈). `H08_B4`가 처음부터 남은 목록에 없는 것은 `BreakAllowed` 조건(소환검·자상 등) 때문으로 보임.
- T33(5차 보우마스터·히어로·비숍, 무적): 판 자동 진행으로 돌파 카드 여러 번 + 마법의 서 2번.
  - 저장 키: `A09=4 A13=1+3 Bowmaster.Hyper=3+4 Bowmaster.Main=4+5 Bowmaster.Sub=3+5 Bowmaster.Tech=4 Bowmaster.Ult=1` → 칸 스킬은 `직업.칸`, 숨은 패시브 스킬은 스킬 Id 키. 카드가 숨은 스킬(A13·A09)도 냄.
  - `BookInfo` = `A06:2:1,A04:2:1,A14:1:2,A10:2:1,A15:1:2,A13:2:1,A09:1:2` — 얻은 수가 위 저장 키 수와 모두 같음.
  - 마법의 서 사용: `RequestBookUse("A14")` → 카드 `A14_B4/A14_B5` → 고른 뒤 `BOOK` 복귀, 스킬석 −1. 숨은 스킬 `RequestBookUse("A13")`도 카드 `A13_B3/A13_B5`가 나오고 얻은 수 +1(서버 RPC로는 가능).
  - **화면 문제(U-A)**: 마법의 서 줄이 5개라 5차는 숨은 스킬 2개(히어로는 1개)가 모두 화면 밖. 4차도 4직업은 숨은 스킬 1개가 화면 밖(칸 4 + 숨은 2 = 6). 문서 4-E "숨은 스킬도 마법의 서 대상"과 어긋남. 돌파 카드로는 얻을 수 있어 막히지는 않지만, 플레이어가 고를 수 없다.

### 2-4. 근접 free cast (C안)와 하이퍼

- 30층 5차 A·V·H 판 로그: 닿지 않는 히어로가 `free cast ... job=Hero ids=H12`(궁극기), `ids=H11`(에픽 어드벤쳐), `ids=H10`(발할라) 시전. T24에서 막혔던 "게이지 100인데 시전 못 함"은 해소. 궁극기 게이지 가득 상태로 머문 시간 히어로 0초·바이퍼 0.7초.
- 판 시작 직후(몬스터가 걸어오는 동안) 전원이 하이퍼·쿨타임 버프를 쓰는 것 확인(의도).
- **발할라(H10) 재시전 (B-A)**: 판 시작 직후 1회 뒤 다음 시전이 147초 뒤(A·V·H 판 로그 05:26:14 → 05:28:41), H·B·N 판 측정에서도 150초 중 시전 1회(78초). 다른 하이퍼는 50~52초 간격(B10·N11·A10·V10 150초에 3~4회). 원인은 `HeroCombat.PickCooldownCast`의 `not (sk.id == "H10" and self._T.valCharge > 0)` — 발할라 충전은 직접 공격으로만 줄어드는데 닿지 않는 히어로는 직접 공격을 거의 못 해(닿음 4~6%) 충전이 남아 쿨이 끝나도 다시 쓰지 않는다. 하이퍼 체감 주기가 40초가 아니라 90~150초 → **문제로 판단**. 수정안: 충전이 남아 있어도 쿨이 끝나면 새로 시전(충전 갱신)하거나, 충전에 지속 시간(예: 20초)을 둔다.

### 2-5. 시간 충전이 전투 상태에서만 도는지

- 10층 5차 판 70초를 0.1초마다 상태별 게이지 증가량으로 나눔: `BOOK 0.4초 BREAK 0.8 CLEAR 10.8 ENTER 7.1 FADE 4.3 ROUTE 2.7 SHOP 0.3 WALK 4.2 / FIGHT-걸어오는 중 39.2초 / FIGHT-도착 0.1초`. 게이지 증가: 비전투 상태는 `CLEAR` 때 구성원마다 0.4(전투 마지막 프레임 누적분)뿐, 나머지 0. → **통과**.
- 마법의 서(BOOK) 상태에서 서버 게이지 58 고정 3초 유지 확인.
- **B-B (설계상 문제)**: `TickUltTime`은 "맨 앞 몬스터가 자기 칸에 도착해 멈춘 동안(`Moving == false`)"만 충전한다. 그런데 원거리 동료가 있으면 맨 앞 몬스터가 걸어오다 죽는 경우가 대부분이라, 10층에서는 전투 39.3초 중 0.1초, 30층에서는 전투 101~113초 중 21~33초만 충전된다. 근접 구성원이 시간 충전으로 궁극기를 쓰게 한다는 4-D 보완 목적이 저·중층에서는 거의 이뤄지지 않는다(3-2 표).

### 2-6. 디버그 판 저장 막기 (4-D 보완 B3)

- 클리어: 5차로 `DebugStartFloor(25)` → `DebugFinishFloor()` → `RESULT`, `debug run boss clear: cleared floor/diamonds not saved`, `debug run clear: best floor/stars not saved`. 저장소 전후 `OrbisTower {"best":20}` 그대로, 별 문서 길이 150 그대로(25층 기록 없음), `ClearedFloor 20`, 롤스터 `dia=3000` 그대로.
- 패배: 1차로 `DebugStartFloor(90)` 무적 끔 → `debug run defeat: best floor not saved floor=90 best=20`, 저장소 `{"best":20}` 그대로.
- **저장된 것**: 계정 경험치(클리어 1번에 +200), 판 보상 깃털·스킬북(+28·+60), 주문서 등. 이번 테스트 중 디버그 판만으로 계정 경험치가 633 → 3511(계정 Lv3 → Lv6)로 올랐다. 계정 Lv6 보상(공격력 +10%)이 테스트 중간부터 켜져 밸런스 측정에도 섞였다(4-3 주의). → 질문 Q1.
- `RequestRetry`(결과 화면 재도전)는 `SelectedStage`로 시작하므로 디버그 판 뒤 재도전은 일반 판이 된다(정적 확인, 문제 없음).

## 3. 4-G 밸런스 측정

### 3-1. R 값 (T34)

- 방법: 7-4대로 편성 히어로·비숍·나이트로드, 같은 레벨·차수, `DebugStartFloor(층)` → 무적 → 첫 `FIGHT`부터 30초씩 두 구간, `R = (준 피해 ÷ 시간) ÷ normalHp(그 스테이지 일반 몬스터 기본 체력)`.
- 기준: 4-B 보완 3 `R0 = 0.675`, 합격 범위 0.47~1.01.

| 조합 | 레벨·차수 | 층 | 구간1 dps / normalHp / R | 구간2 dps / normalHp / R | 평균 R | R ÷ R0 | 구성원 공격력(H/B/N) |
|---|---|---|---|---|---|---|---|
| P1 | Lv1 1차 | 5 | 27.2 / 70 / 0.388 | 24.7 / 70 / 0.352 | 0.37 | 0.55 | 41 / 37 / 45 |
| P2 | Lv10 2차 | 14 | 52.3 / 160 / 0.327 | 66.2 / 187(2스테이지) / 0.354 | 0.34 | 0.50 | 54 / 49 / 59 |
| P3 | Lv20 4차 | 37 | 108.2 / 312 / 0.347 | 123.7 / 455(2스테이지) / 0.272 | 0.31 | 0.46 | 80 / 73 / 88 |
| P4 | Lv30 5차 | 60 | 164.2 / 620 / 0.265 | 246.5 / 723(2스테이지) / 0.341 | 0.30 | 0.45 | 100 / 94 / 114 |

- **불합격**: 네 조합 모두 0.7 × R0 미만. 네 조합 R이 서로 비슷(0.30~0.37)하므로 "차수·레벨 사이의 균형"은 맞고, **전체가 7절 기대보다 약 2배 약하다**. 고레벨일수록 조금 더 약해진다(P1 0.55배 → P4 0.45배).
- 측정 계정: 계정 Lv3(공격력 +10%·체력 +10%), 각인 `Tough 3·Regen 3·Drain 3·Bulwark 3`, 은총 5칸, 유물 21종, 1단계 장비. R0도 같은 계정 기준이다.

### 3-2. 궁극기 주기 (전투 시간 기준)
