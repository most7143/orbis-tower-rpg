**스킬 표 (`Data/HeroSkillTable.csv`)**
- 맨 끝에 `JobId` 열을 추가했다. 기존 히어로 줄은 모두 `Hero`.

- 장착 칸 키: 히어로는 예전대로 `"1"`~`"5"`, 다른 직업은 `"Bishop:1"`~`"Bishop:5"`. 예전 저장과 호환된다.

- 뽑기: 모든 직업 스킬이 한 풀에 섞여 있다 (등급 확률 → 그 등급에서 균등).
- 합성: 같은 직업 안에서만 상위·같은 등급 스킬이 나온다.
- 비숍 고유 패시브 **성수 레벨**: `HolyWaterLv` (저장 키 `hw`, 기본 1, 최대 11). `RequestHolyWaterUpgrade()`로 스킬북을 써서 올린다.

- `SkillRunDataFor(job)`: 판 시작용 장착·레벨·콤보 레벨·성수 레벨. `SkillRunData()`는 히어로용으로 남겼다.

## 2. TowerRunManager에 추가한 것

**속성**

**캐릭터 단위 처리** (메서드)
- 히어로 찾기: `HeroOf`, `MainHero`, `Heroes`, `Actors`
- 상태 확인: `IsCompanion`, `IsDown`
- 체력·보호막: `ActorMaxHp`, `ActorHp`, `HealActor`, `ShieldOf`, `AddShield`, `FullHealParty`

**동료 관리**
- 생성·제거·코스튬: `SpawnCompanion`, `DestroyCompanion`, `CopyCostumeToCompanion`
  - 코스튬은 `Custom*Equip` 값을 복사한다. 서버에서 `GetEquip`이 nil을 돌려주기 때문이다.
- 부활: `ReviveCompanion`, `ReviveDowned`
- 피격: `ApplyCompanionDamage`

**전투 흐름**
- 공격 대상: `PickTarget`. 위협은 지금 거리만 반영한다.
  - 메인 1.5, 동료 1.0
  - 맨 앞 몬스터는 위협 1위를 노리고, 줄 선 몬스터는 비율에 따라 무작위로 고른다.
- 기본 공격: `ActorAttack(actor, monster, main)`
  - 캐릭터마다 공격 타이머가 따로 있다 (동료는 `_T.compAtkTimer`).
  - 연속 베기와 메소 사냥꾼은 메인에만 붙는다.
- 함수 인자 변경
  - `BasicHitDamage(hero)`, `RollJobProcs(hero)`
  - `ApplyJobProcs(procs, target, attacker)`: 공격한 캐릭터의 히어로가 스킬을 적용한다.
- 매 프레임
  - 두 히어로 모두 `Tick` / `PauseClock`
  - 몬스터 등장 시 두 히어로 모두 `OnMonsterSpawn`
  - 암흑 확률은 두 히어로 중 큰 값을 쓴다.

**쓰러짐·부활**
- 메인이 쓰러졌는데 동료가 살아 있으면 `PlayerDown`이 되고 전투는 계속된다.
- 둘 다 쓰러지면 `Defeat()`.
- 웨이브(스테이지)를 끝내면 쓰러진 캐릭터가 30%로 일어난다.

**동료 위치**
- 몸체가 없어 발판에 내려앉지 않는다.
- 그래서 전투 중에는 메인의 발 높이에 맞춘다.

## 3. TowerPlayer에 추가한 것

- `OwnerUserId`(동기화)와 `Uid()`
  - 동료는 주인 플레이어 UserId로 클라이언트와 통신한다 (공격 동작, 타격 요청).
- 동료 공격 동작: 플레이어 컨트롤러가 없어서 `BodyActionStateChangeEvent`(Attack → 0.6초 뒤 Stand)를 쓴다.
- `SetDownPose(down)` (Multicast): 동료 쓰러짐·일어남 자세.

### 검증 방법 (다시 할 때)

1. stop → refresh → play.
2. 서버에서 플레이어를 `OrbisTower`로 텔레포트한다.
3. 클라이언트에서 `mgr:RequestPickJob(히어로 칸)`을 부르고, 카드가 뜨면 `RequestPick(1)`을 반복하는 스크립트를 켠다.
4. 서버 스크립트로 아래를 확인한다.
   - **`RunState == "FIGHT"`인 순간**에 `ApplyPlayerDamage(99999)`를 두 번 부른다 → `PlayerDown`이 되는지.
   - 5초 뒤 `CompanionHp`가 줄었는지.
   - `ApplyCompanionDamage(99999)` → `RunState`가 `DEFEAT`가 되는지.

## 5. 남은 일

### 1단계에서 정리한 것 (2026-11-18 추가)
- **몬스터 상태 공유 완료.** 메인 히어로가 몬스터 상태 담당(`MS()`)을 맡는다.
  - 공유 대상: 자상, 디버프, 기절 표시, 줄 선 몬스터 상태.
  - 동료 히어로는 부여·소비·표시를 담당에게 넘긴다 (`AddBleedStacks`, `AddQueuedBleed`, `ConsumeBleed`, `ApplyDebuff`, `StunTarget` 등).
  - 시간 경과 처리(Tick)는 담당만 한다.
  - 연결은 판 시작 때 매니저의 `LinkStatusOwner()`가 한다.
- **원래 있던 버그 수정: 첫 자상이 덜 쌓이던 문제.**
  - 증상: 몬스터 등장 직후 첫 부여에서 3중첩이 1 또는 0으로 들어갔다.
  - 원인: `_T` 안의 표를 고친 뒤 다시 넣지 않으면 변경이 남지 않는 경우가 있었다.
  - 조치: 목록을 고친 뒤 `self._T.bleed = list`로 다시 저장한다.
  - 다른 직접 수정 코드에도 같은 위험이 있을 수 있다.
- 다른 컴포넌트의 `_T`를 바깥에서 직접 쓰면 반영되지 않을 수 있다. 공유 상태는 반드시 담당 컴포넌트의 메서드로 바꾼다.
