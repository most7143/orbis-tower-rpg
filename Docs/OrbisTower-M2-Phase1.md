## 상태 체크리스트
> 상태: ⬜ 시작 전 · 🟡 구현됨(테스트 전) · ✅ 테스트 완료
> 모두 ⬜에서 시작. 만들면 🟡, 확인까지 끝나면 ✅.
> AI가 직접 확인할 수 없는 항목은 "사용자 테스트 필요"를 달고 🟡로 둔다.

- ✅ 1. 테스트 옵션 끄기 (특성 카드 미스틱 확정 해제) — 플래그 false 확인, 실제 선택 등급 샘플(2·1·3 / 2·1·2 / 2·3·1 / 1·2·2)에 강제 미스틱 없음
- 🟡 2. 스킬 테스트 버튼·맵 출시 처리 — 결정: 메이커 플레이에서만 표시 (`Environment:IsMakerPlay()`). 메이커에서 표시 확인  ⚠️ 사용자 테스트 필요: 출시(퍼블리시) 월드에서 버튼이 숨겨지는지
- ✅ 3. 판 진행 핵심 동작 일괄 점검 (전투·층·보상·레벨·패배 초기화·중단하기) — 전투→처치→보상→레벨업→스테이지/층 상승→엘리트→깃털, 중단하기→확인→패배→결과 팝업→다시 도전(1층·Lv1·메소 0) 확인
- 🟡 4. 전투 능력치 동작 확인 (방어력·크리티컬·명중↔회피) — 공식은 코드로 확인(방어: def/(def+100), MISS: 몬스터 회피−명중, 크리 확률·배율 전달)  ⚠️ 사용자 테스트 필요: 실제 수치 체감
- ✅ 5. 패시브 스킬 10종 + 스킬석 강화 + 스킬 탭 확인 — 레벨 해금(Lv1·3·5), 스킬석 강화 성공·실패와 이펙트 확인
- ✅ 6. 공격 모션·피격·사망 연출·데미지 숫자 확인 — 공격 모션·데미지 숫자 화면 확인, 사망 애니메이션 1회 재생 로그 확인
- ✅ 7. 특성 발현·전직·직업 스킬 / 보스 거래 확인 — 시작 5장·레벨업 3택, 100포인트 1차 전직(포인트 초기화·직업 스킬), 보스 거래(천사) 적용 확인
- ✅ 8. 아웃게임 확인: 각인 / 심볼 / 은총 (효과 적용 + 저장·불러오기) — 각인·심볼·은총 불러오기, 판 시작 능력치 반영, 깃털 저장 후 재시작 시 7→11 유지 확인
- ✅ 9. 효과음 보강: 레벨업·버튼 클릭 — 레벨업 축하음, 모든 UI 버튼 공통 클릭음(`Game/UISoundLogic`) 재생 확인 (소리 크기·어울림은 취향에 맞게 조정 가능)
- ✅ 10. 남은 수치 데이터 이전 (보상·경험치·강화 비용 상수 → 데이터셋) — `Data/RunConfig` 39개 값, 이전 전후 보상·경험치 동일 확인
- 🟡 11. 1차 밸런스 (한 판 5~15분 목표) — 초반 스테이지 약 5초, 층(10스테이지) 약 1분 → 5~15층 도달 시 5~15분  ⚠️ 사용자 테스트 필요: 실제 플레이 체감
- 🟡 12. 화면·카메라 모바일 확인 — 메이커 모바일(태블릿 4:3) 미리보기에서 탭·하단 바·이름표 겹침 없음 확인  ⚠️ 사용자 테스트 필요: 실기기(휴대폰)
- 🟡 13. 플레이어 조작 비활성화 확인 — 전투 중 방향키·점프 입력 시 위치 변화 없음 확인 (단, PlayerControllerComponent는 켜져 있음)  ⚠️ 사용자 테스트 필요: 실제 조작

## 작업 상세

### 1. 테스트 옵션 끄기 (특성 카드 미스틱 확정 해제)
- **목표**: 특성 카드가 실제 확률(일반50/희귀30/에픽14/레전더리5/미스틱1%)로 나온다.
- **필요한 시스템**: `Tower/TowerRunManager.mlua` 83·85행 `TestFirstPickTopGrade`·`TestAlwaysTopGrade`를 `false`로. 사용처는 565행 한 곳.
- **데이터**: `Data/TraitGradeTable` (확률 확인만).
- **완료 기준**: 판을 시작해 특성 선택을 여러 번 뽑는 `maker_execute_script` 검증 스크립트로 등급 분포를 `[VRF]` 로그로 남겨, 미스틱이 매번 나오지 않음을 확인 — AI 확인 가능.
- **의존**: 없음. **가장 먼저** 한다(이후 모든 확인이 실제 확률 기준이 되도록).
- **참고 스킬**: msw-scripting (`references/verify-checklist.md`).

### 2. 스킬 테스트 버튼·맵 출시 처리
- **목표**: 개발 중에는 로비 [스킬 테스트] 버튼과 `SkillTest` 맵을 계속 쓰되, 출시 빌드에서는 버튼이 보이지 않는다.
- **필요한 시스템**: `Lobby/LobbyUILogic.mlua` (`btnSkillTest` 바인딩 32행, `OnSkillTest` 66행). 방식 후보: (A) `Environment:IsMakerPlay()`일 때만 버튼 표시, (B) 로비 로직에 `ShowDevTools` 속성 하나 두고 출시 전 끄기. **방식은 작업 시작 시 사용자에게 확인**.
- **UI**: `ui/LobbyUI.ui`의 `Root/BtnSkillTest` (Enable 토글만, 레이아웃 변경 없음).
- **완료 기준**: 메이커 플레이에서 버튼 표시 / 출시 조건에서 숨김을 `[VRF]` 로그로 확인 — AI 확인 가능 (방식 A는 출시 빌드 실기 확인이 추가로 필요할 수 있음).
- **의존**: 없음.
- **참고 스킬**: msw-scripting, msw-ui-system (`references/runtime-patterns.md`).

### 3. 판 진행 핵심 동작 일괄 점검
- **목표**: 자동전투 → 처치 → 메소·경험치 → 레벨업 → 다음 스테이지/층 → 패배 시 결과 팝업 → 1층 초기화, 그리고 [중단하기] → 확인 창 → 부활 효과 무시하고 바로 패배까지 한 판 흐름이 끊김 없이 돈다.
- **필요한 시스템**: `TowerRunManager` (`Defeat` 1311행, `RequestGiveUp` 1332행), `ResultPopupLogic`, `MainPanelLogic.ShowConfirm`.
- **완료 기준**: 검증 스크립트로 몇 스테이지 진행 → 강제 패배 → 결과 팝업 값(도달 층·레벨·메소·최고 기록) 확인, 다시 [중단하기] 경로로 한 번 더 — `[VRF]` 로그 + 스크린샷. AI 확인 가능.
- **의존**: 1.
- **참고 스킬**: msw-scripting (`references/verify-checklist.md`).

### 4. 전투 능력치 동작 확인
- **목표**: 방어력(받는 피해 감소)·크리티컬(확률·배율)·명중↔몬스터 회피(MISS)가 공식대로 적용된다.
- **필요한 시스템**: `TowerRunManager`·`TowerPlayer`의 데미지 계산.
- **완료 기준**: 능력치를 극단값으로 바꿔 넣는 검증 스크립트로 피해량·크리티컬 비율·MISS 비율을 로그로 확인 — AI 확인 가능. **체감(너무 세다/약하다)은 사용자 테스트 필요**.
- **의존**: 3.
- **참고 스킬**: msw-combat-system.

### 5. 패시브 스킬 10종 + 스킬석 강화 + 스킬 탭 확인
- **목표**: 레벨 해금 → 스킬석으로 강화(확률 50%→5%씩 감소) → 효과 적용, 스킬 탭의 잠김/해금/강화 가능 표시가 맞다.
- **데이터**: `Data/SkillTable`.
- **UI**: `ui/MainPanel.ui` 스킬 탭.
- **완료 기준**: 스킬석을 지급하는 검증 스크립트로 강화 성공·실패와 효과 수치 변화를 로그로 확인 + 탭 스크린샷 — AI 확인 가능.
- **의존**: 3.
- **참고 스킬**: msw-scripting.

### 6. 공격 모션·피격·사망 연출·데미지 숫자 확인
- **목표**: 플레이어 공격 동작과 타격 시점이 맞고, 몬스터 피격 모션·사망 애니메이션 1회 재생·시체 제거, 데미지 숫자(플레이어 피격은 보라색)가 나온다.
- **완료 기준**: 플레이 중 연속 스크린샷 + 사망 처리 `[VRF]` 로그 — AI 확인 가능. 타격감 자체는 사용자 판단.
- **의존**: 3.
- **참고 스킬**: msw-avatar, msw-combat-system.

### 7. 특성 발현·전직·직업 스킬 / 보스 거래 확인
- **목표**: 판 시작 5장 → 레벨업마다 3택 → 100포인트 전직(포인트 초기화, 최대 3차) → 직업 스킬 발동(이펙트·추가 피해). 층 보스 처치 후 천사/악마/상인 거래 3택 → 효과·대가가 이번 판에만 적용.
- **데이터**: `TraitTable`·`TraitGradeTable`·`JobSkillTable`·`DealTable`.
- **완료 기준**: 특성 포인트를 지급해 1·2·3차 전직까지 진행하는 검증 스크립트 + 보스 처치 후 거래 선택 3종 각각의 효과를 로그로 확인 — AI 확인 가능.
- **의존**: 1, 3.
- **참고 스킬**: msw-scripting.

### 8. 아웃게임 확인: 각인 / 심볼 / 은총
- **목표**: 각 시스템의 효과가 판 시작 시 적용되고, 저장 후 다시 들어와도 그대로 불러와진다.
- **필요한 시스템**: `Engrave/PlayerEngrave` (저장 키 `OrbisEngrave`·`OrbisSymbol`·`OrbisGrace`), 각 UI 로직.
- **완료 기준**: 각인 투자 / 심볼 획득 / 은총 돌리기 후 플레이 재시작 → 값 유지와 판 시작 시 효과 적용을 로그로 확인 — AI 확인 가능. ⚠️ 저장 확인 중 DataStorage 호출이 반복되지 않게 할 것(`references/datastorage.md`).
- **의존**: 3.
- **참고 스킬**: msw-scripting (`references/datastorage.md`).

### 9. 효과음 보강: 레벨업·버튼 클릭
- **목표**: 레벨업 순간과 주요 버튼(로비·탭·강화·확인)에 효과음이 난다. 몬스터 피격·사망음은 이미 있음.
- **필요한 시스템**: `_SoundService:PlaySound` (현재 `TowerMonster.mlua`에서만 사용 중 — 같은 방식으로). 레벨업은 `TowerRunManager`의 레벨업 이펙트 재생 지점(1210행 근처).
- **완료 기준**: 효과음 리소스를 msw-search로 찾아 적용, 재생 호출 `[VRF]` 로그 확인 — AI 확인 가능. 소리 크기·어울림은 사용자 판단.
- **의존**: 없음.
- **참고 스킬**: msw-search, msw-ui-system (`references/ui-sound.md`).

### 10. 남은 수치 데이터 이전
- **목표**: `TowerRunManager`에 하드코딩된 보상·경험치·강화 비용 상수(`BaseMesoReward`·`MesoGrowth`·`BaseExpReward`·`ExpGrowth`·`BaseExpToNext`·`ExpToNextGrowth`·`EliteRewardMul`·`UpgradeCostMul`·`EnhanceCostStep`·`StoneDropChance` 등)를 데이터셋으로 옮겨, 밸런스 조정 시 코드를 고치지 않게 한다.
- **데이터**: 새 `Data/RunConfig` (키-값 한 줄씩 구조), 기존 값 그대로 옮김 → 동작 변화 없어야 함.
- **완료 기준**: 이전 전후 같은 시나리오(검증 스크립트)의 보상·경험치 수치가 동일함을 로그로 확인 — AI 확인 가능.
- **의존**: 3 (전후 비교 기준).
- **참고 스킬**: msw-general (`references/dataset.md`), msw-scripting.

### 11. 1차 밸런스 (한 판 5~15분 목표)
- **목표**: 실제 확률(작업 1)과 데이터셋(작업 10) 기준으로, 평범하게 했을 때 한 판이 5~15분 안에 끝난다.
- **완료 기준**: 검증 스크립트로 자동 진행 시간을 재 대략적인 판 길이를 로그로 확인(AI) → **실제 체감은 사용자 테스트 필요**.
- **의존**: 1, 10.
- **참고 스킬**: msw-scripting.

### 12. 화면·카메라 모바일 확인
- **목표**: 모바일 화면에서 전투 장면·왼쪽 탭·패널·하단 바·HP 바·이름표가 겹치지 않고 보인다.
- **완료 기준**: `maker_set_platform`으로 모바일 전환 후 스크린샷으로 1차 확인(AI) → **실기기 확인은 사용자 테스트 필요**.
- **의존**: 없음 (마지막에 몰아서 사용자 테스트로 요청).
- **참고 스킬**: msw-ui-system (`references/ui-fundamentals.md` §9).

### 13. 플레이어 조작 비활성화 확인
- **목표**: 전투 중 방향키·점프·공격 키를 눌러도 캐릭터가 움직이거나 따로 공격하지 않는다.
- **완료 기준**: `maker_keyboard_input`으로 키 입력 후 위치 변화 없음을 로그로 1차 확인(AI) → **실제 조작 확인은 사용자 테스트 필요**.
- **의존**: 없음.
- **참고 스킬**: msw-defaultplayer.
